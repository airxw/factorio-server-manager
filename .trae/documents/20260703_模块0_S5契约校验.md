## 四、继承性已知偏差（P1-P5 文档已记录）

### 4.1 P4 偏差
- `ListMonitorSnapshotsQuery` 契约用 `start/end`，实现用 `from/to`（前后端一致）
- `MonitorSnapshotSummary.json_extra` 字段名（非 `extra`）
- `CreateMonitorSnapshotRequest` 无 `timestamp` 字段，后端用 `now()`
- `DeleteListEntryResponse` 为 `{player_name, deleted}`（含 player_name）
- `req.user.userId`（JWT 字段名，非 `id`）

### 4.2 P5 偏差
- `webhook_deliveries` 表未创建（migration 20260703000012 仅 webhooks + audit_logs）
- triggerTest 不持久化投递记录，仅返回即时结果
- audit_logs 表暂无数据写入（需后续在各 service 中注入 auditLogService.create）
- `enabled` 字段 SQLite 返回 1/0 而非 boolean
- triggerTest SSRF 风险（仅 admin 可调用，无 URL 白名单）

### 4.3 P1-P3 继承偏差
- shopService 未 `implements @public/interface_stub/shop-service.d.ts`
- pack.yaml 命令模板字段是 `business.shop.give_command`
- `/api/users` 返回字段比 `AdminUserSummary` 类型少
- vipPermissions POST 冲突响应码用 `PANEL_VALIDATION_ERROR + 409`
- itemSync 路由未套 requireAdmin（与 P4/P5 全套 requireAdmin 不一致）
- claiming 超时回滚定时任务未实现
- player.ts 混合权限暂统一套 requireAdmin（普通用户 histories/claims 暂需 admin 代查）
- React 实际版本 19 + react-router-dom v7

## 五、修复方案

### 5.1 S5 阶段不修复 .d.ts 存根
**理由**：
1. `public/` 路径受 rules-0 §四-10 + rules-4 §4.3 + ec7_action_gate 三重保护，修改需人类显式授权 + 走 s0601 流程
2. 7 项偏差均不影响 HTTP 外部契约和功能运行（client.ts ↔ routes 完全对齐）
3. 修复涉及 .d.ts 重写 + 实现重写 + 价值判断（业务方法风格 vs CRUD 风格），属于架构层调整
4. 应在 S7 运维阶段统一通过 s0601（适配契约变更）+ s0602（技术债扫描）流程处理

### 5.2 S7 阶段对齐策略（建议）
1. 评估"业务方法风格"（installMod/toggleMod）vs "CRUD 风格"（create/update）哪个更符合通用游戏服务器面板定位
2. 通过 s0601 流程同步更新 .d.ts 存根 + 实现 + 测试用例
3. 优先处理影响功能的偏差：
   - monitorService.checkThreshold（告警功能缺失）
   - webhookService.triggerWebhook（自动触发链路缺失）
   - audit_logs 写入注入（审计日志无数据）
   - claiming 超时回滚定时任务
