# 接入六大核心功能到四个 Pack 的自动化链路

## 一、问题分析

### 问题现象

用户要求一次性完成 6 大核心功能在 4 个剩余 pack（minecraft-vanilla、ark-vanilla、rust-vanilla、palworld-vanilla）上的接入：

1. **玩家加入**：聊天触发器自动检测加入事件，欢迎语 + 礼包命令一键下发
2. **绑定实例·获得 VIP**：VIP 等级自动匹配，商城与特权命令入口解锁
3. **商城消费·自动到账**：下单后命令模板自动渲染并下发到游戏服
4. **CDK 兑换·额外奖励**：玩家输入兑换码后自动触发奖励命令
5. **聊天互动·社区活跃**：关键词触发器响应玩家聊天，定时消息保持服务器活跃度
6. **投票自治·共建社区**：阈值触发自动执行

### 影响范围

- 4 个 pack（minecraft/ark/rust/palworld）的 6 大功能自动化链路
- index.ts 事件订阅与调度任务注册
- voteService 阈值触发后处理
- periodicMessageService 到期消息处理
- chatTrigger 关键词自动响应

### 根因分析

#### 根因 1：PLAYER_JOIN 事件订阅缺失

- `index.ts` 的 `dispatchPackConsoleEvents` 已正确 emit `PLAYER_JOIN` 事件并调用 `playerService.recordJoin`
- **缺失**：没有任何订阅者监听 `PLAYER_JOIN` 事件来自动下发 `pack.business.chat_enhancement.welcome.first_gift_command`
- → 玩家加入游戏后不会自动收到欢迎礼包

#### 根因 2：PERIODIC_MESSAGE 调度任务未注册

- `scheduler` 已支持 `PERIODIC_MESSAGE` 任务类型常量
- `periodicMessageService` 只有 CRUD，没有"获取到期消息并下发"的方法
- `index.ts` 没有注册 `PERIODIC_MESSAGE` 周期任务
- → 定时消息永远停留在 DB 中不会下发到游戏服

#### 根因 3：chat trigger 关键词自动响应缺失

- `dispatchPackConsoleEvents` 中只调用 `chatLogService.parseAndStore`，未触发 `CHAT_EVENT` 事件
- 没有 chat trigger 关键词匹配逻辑，未自动下发响应命令
- → 玩家发送关键词不会触发自动响应

#### 根因 4：voteService 阈值触发后无自动执行

- `voteService.castVote` 中阈值满足时只更新 status='passed'，没有 emit `VOTE_THRESHOLD_MET` 事件
- 没有订阅者下发 kick 等执行命令
- → 投票通过后只是 DB 状态变更，无实际动作

#### 根因 5：4 个 pack 的 yaml 配置需验证

- 摘要显示 4 个 pack 已有完整 business/event_parsers/items 配置
- 需验证 chat_enhancement.welcome.enabled、periodic_messages.enabled、event_parsers 等字段针对各自游戏正确

### 已确认已有的基础设施

- `eventBus`（EventBusImpl 单例）：预定义事件 PLAYER_JOIN/PLAYER_LEAVE/CHAT_EVENT/ORDER_CLAIMED/CDK_REDEEMED/VOTE_THRESHOLD_MET
- `scheduler`（SchedulerImpl 单例）：支持 interval_ms 周期任务，已注册 OPTIMISTIC_LOCK_TIMEOUT_SCAN 和 COMMAND_QUEUE_PROCESS
- `commandDispatcher`：命令队列系统，入队 → 每 5s processQueue → daemonClient 发送
- `dispatchPackConsoleEvents`：解析 daemon console.output 事件，emit PLAYER_JOIN/PLAYER_LEAVE 到 eventBus
- webhook 已订阅 ORDER_CLAIMED/CDK_REDEEMED/VOTE_THRESHOLD_MET（但 VOTE_THRESHOLD_MET 无人 emit）
- shopService.claimOrder → 入队 commandDispatcher ✅
- cdkService.redeemCdk → 入队 commandDispatcher ✅

## 二、修复方案

### 方案 A：补全 PLAYER_JOIN 事件订阅（功能 1）

在 `index.ts` 的 main() 函数中，`playerService` 初始化之后添加：

```typescript
eventBus.on(PLAYER_JOIN, (payload) => {
  // payload: { server_id, player_name }
  void handlePlayerJoinWelcome(payload).catch(...);
});

async function handlePlayerJoinWelcome({ server_id, player_name }) {
  // 1. 查询 pack.business.chat_enhancement.welcome
  // 2. 若 !welcome.enabled 则返回
  // 3. 渲染 first_gift_command 模板（替换 {{player}}）
  // 4. 通过 commandDispatcher.dispatch 入队下发
  // 5. 调用 playerService.recordGiftClaim 防重复（按日去重）
}
```

### 方案 B：补全 PERIODIC_MESSAGE 调度任务（功能 5）

1. 在 `periodicMessageService.ts` 新增 `getDueAndAdvance()` 方法：
   - SELECT * FROM periodic_messages WHERE enabled=1 AND next_run_at <= now
   - 对每条记录 UPDATE next_run_at = now + interval_minutes
   - 返回到期消息列表

2. 在 `index.ts` 中：
   - 注册 `scheduler.schedule({ type: PERIODIC_MESSAGE, interval_ms: 60_000 })`
   - 在 scheduler executor 中处理 PERIODIC_MESSAGE 类型：
     - 获取到期消息列表
     - 渲染 `pack.business.chat_enhancement.periodic_messages.broadcast_command`（替换 {{message}}）
     - 通过 commandDispatcher 下发

### 方案 C：补全 chat trigger 关键词自动响应（功能 5）

1. 修改 `dispatchPackConsoleEvents`：在 chat 解析后 emit `CHAT_EVENT` 事件
2. 在 `index.ts` 中订阅 `CHAT_EVENT`：
   - 查询该 server 的 chat triggers（关键词规则）
   - 匹配命中后渲染响应命令并下发

### 方案 D：补全 vote 阈值触发自动执行（功能 6）

1. 修改 `voteService.castVote`：阈值满足时 `eventBus.emit(VOTE_THRESHOLD_MET, { server_id, vote_id, target, reason })`
2. 在 `index.ts` 中订阅 `VOTE_THRESHOLD_MET`：
   - 渲染 `pack.business.players.kick_command`（替换 {{player}} {{reason}}）
   - 通过 commandDispatcher 下发 kick 命令

### 风险评估

- **方案 A**：低风险。仅新增事件订阅，不改既有 emit 逻辑；playerService.recordGiftClaim 已有 gift_claims 表
- **方案 B**：低风险。新增独立方法和调度任务，不影响既有流程
- **方案 C**：中风险。chat trigger 规则需要从 DB 读取，注意错误隔离
- **方案 D**：低风险。voteService.castVote 已有阈值判定，仅追加 emit + 订阅下发
