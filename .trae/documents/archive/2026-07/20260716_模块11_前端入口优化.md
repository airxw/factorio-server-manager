# 模块11 前端入口补齐与导航优化

## 第一章：问题分析

### 1.1 问题现象

模块10「游戏内聊天命令交互能力补齐」已完成 12 个 Task 并通过端到端验证，但用户在前端使用过程中暴露 4 个核心问题：

1. **新增功能无入口可见**：PlayerVerify / PlayerBindings / ChatTriggers / PlayerJoinSettings 4 个新页面虽然在 App.tsx 中注册了路由，但 Layout.tsx 侧边栏导航完全没有这些链接，用户只能手工输入 URL 才能访问，等同于"功能存在但用户找不到"。
2. **操作逻辑错位**：ChatTriggers 和 PlayerJoinSettings 本质是「实例作用域」的设置（页面顶部用下拉选择服务器），却放在 `/admin/*` 路径下，违背了 v2.0.0 spec 确立的「实例中心化」设计原则。用户在 admin 入口下找不到也想不到这些功能在 admin 路径下。
3. **页面不够好看（违反样式规范）**：PlayerVerify.tsx 含大量内联样式（fontSize / fontWeight / letterSpacing / padding / background / borderRadius / margin / fontFamily 等），违反了已完成的 `frontend-comprehensive-ui-polish` spec 的 AC-10「静态内联样式数量从 40+ 减少到 5 处以内（仅限动态值）」的清除要求；Profile.tsx 第 368 行也有 1 处 `marginBottom` 内联样式。
4. **isAdminRole 角色 bug 未修复**：20 个 admin 页面（含模块10 新增的 3 个）的 `isAdminRole` 函数只识别 `admin`/`system_admin`，不识别当前 3 级角色体系下的 `server_admin`，导致当前种子管理员（role=server_admin）访问 admin 页面会被显示"无权限访问该页面"。

### 1.2 影响范围

| 影响维度 | 范围 |
|---------|------|
| 前端组件 | Layout.tsx + ServerDetail.tsx + ChatTriggers.tsx + PlayerJoinSettings.tsx + PlayerVerify.tsx + Profile.tsx + App.tsx + styles.css + 新增 utils/role.ts |
| admin 页面 | 20 个含 `isAdminRole` 函数的 tsx 文件（PlayerBindings / ChatTriggers / PlayerJoinSettings / ShopItems / Packs / AuditLogs / Webhooks / Lists / Monitor / Backups / Saves / Mods / ChatSettings / PeriodicMessages / VoteSettings / CdkCodes / ItemSync / VipPermissions / SystemConfig / Users） |
| 角色 | 主要影响 `server_admin` 角色（当前种子管理员） |
| 后端 | 无影响（本 spec 纯前端，不涉及 API/DB 变更） |
| public/ 契约 | 无影响（不修改 public/ 下任何文件） |
| 路由 | BREAKING：`/admin/chat-triggers` 和 `/admin/player-join-settings` 直访路由移除，改为重定向到 `/instances` |

### 1.3 根因分析

| 问题 | 根因 |
|------|------|
| 入口缺失 | 模块10 开发时聚焦于功能实现和 API 对接，未同步更新 Layout.tsx 的 `ADMIN_LINKS` 数组 |
| 路由错位 | ChatTriggers / PlayerJoinSettings 在创建时按"管理后台页面"惯例放在 `/admin/*`，但未识别到它们是「实例作用域」的设置，违背实例中心化原则 |
| 样式违规 | PlayerVerify.tsx 是模块10 新增页面，开发时未对齐 `frontend-comprehensive-ui-polish` spec 的 AC-10 内联样式清除要求；Profile.tsx 是历史遗留 1 处 |
| isAdminRole bug | 3 级角色体系（server_admin / instance_admin / user）改造时，未同步更新所有 admin 页面的 `isAdminRole` 函数（Layout.tsx 第 107 行已正确识别 server_admin，但 20 个 admin 页面遗漏） |

## 第二章：修复方案

### 2.1 方案描述

本 spec 不引入新功能，仅做 **入口补齐 + 操作逻辑修正 + 样式合规 + 角色识别修复**，6 项变更如下：

1. **修复 isAdminRole 角色识别（20 个页面统一）**：抽取公共工具函数到 `panel/frontend/src/utils/role.ts`，导出 `isAdminRole` 函数统一识别 `server_admin`/`system_admin`/`admin`；20 个 admin 页面删除本地 `isAdminRole` 定义，改为 `import { isAdminRole } from '../../utils/role'`。
2. **侧边栏导航补全**：在 Layout.tsx `ADMIN_LINKS` 数组中 Webhooks 后新增 `{ to: '/admin/player-bindings', label: '玩家绑定', icon: UserCheck }`，并 import `UserCheck` 图标。
3. **ChatTriggers / PlayerJoinSettings 移入实例详情 tab（BREAKING 路由变更）**：将这两个组件改造为受控组件（接收 `serverId` props，移除内部服务器下拉），在 ServerDetail.tsx 的 `BASE_TABS` 新增 `'chat-triggers'` 和 `'player-join-settings'` 两个底座 tab；旧路由 `/admin/chat-triggers` 和 `/admin/player-join-settings` 重定向到 `/instances`。
4. **Profile 页面加入 PlayerVerify 入口**：在 Profile.tsx「我的实例绑定」卡片下方新增「游戏内绑定验证码」入口卡片，按钮跳转 `/profile/verify`。
5. **PlayerVerify 页面美化（移除内联样式）**：移除 PlayerVerify.tsx 中所有静态内联样式，改用 CSS 类：验证码展示用 `.verify-code-display`、使用方法引导框用 `.verify-code-usage`、`borderColor` 用 `.card-highlight`、`marginTop: 12` 用 `.mt-3`、`fontWeight: 'bold'` 用 `.font-bold`。
6. **Profile 页面移除 1 处内联样式**：第 368 行 `style={{ marginBottom: 12 }}` 改为 `.mb-3` 工具类。

同时配套变更：
- **styles.css 新增 6 个 CSS 类**：`.verify-code-display` / `.verify-code-usage` / `.card-highlight` / `.mt-3` / `.mb-3` / `.font-bold`。
- **新增 `utils/role.ts`**：公共工具函数文件。

### 2.2 替代方案

| 替代方案 | 否决理由 |
|---------|---------|
| 仅补入口不改路由 | 违背实例中心化原则；ChatTriggers/PlayerJoinSettings 在 admin 路径下需要"先选服务器"，操作路径长且语义割裂 |
| 不抽取公共函数，直接修改 20 个文件 | 重复代码 20 份，未来若再增角色（如 instance_admin）需改 20 处；抽取后单点维护 |
| 保留 `/admin/chat-triggers` 直访路由同时提供 tab | 双入口导致用户认知混乱，且组件改造为受控后无法独立渲染（需要 serverId） |

### 2.3 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 路由 BREAKING：用户书签 `/admin/chat-triggers` 失效 | 中 | 新增 `<Navigate to="/instances" replace />` 重定向兜底，用户感知为"被引导到实例列表先选实例" |
| 20 个 admin 页面同时修改 import | 低 | 通过公共函数抽取保证一致性；编译验证（Task 11）兜底；grep 验证残留为 0 |
| styles.css 类名冲突 | 低 | `.mt-3` / `.mb-3` / `.font-bold` 是约定俗成的 Tailwind 风格命名，项目无 Tailwind，无冲突 |
| 受控组件改造遗漏 serverId 传值 | 中 | ServerDetail.tsx 在 tab 渲染分支显式传 `serverId={server.id}`；typecheck 验证 props 类型 |
| 后端/DB 变更 | 无 | 本 spec 纯前端，无后端/DB/public/ 变更 |
| public/ 契约变更 | 无 | 不修改 public/ 下任何文件 |

### 5.3 经验教训

1. **公共函数抽取应前移**：原 spec 假设 20 个页面"已有"`.mt-3`/`.mb-3`/`.font-bold` 工具类是错误的，实际需要 Task 8 显式新增。SubTask 1.0 将 `isAdminRole` 抽取前移为公共函数，避免 1.1-1.4 先本地修复再被覆盖的返工——这是正确的决策。
2. **受控组件改造需同步更新所有调用方**：ChatTriggers/PlayerJoinSettings 改为受控组件后，App.tsx 的直访路由会因缺少 serverId 而 typecheck 失败——Task 5 移除直访路由修复此问题。这类改造应识别全部调用点。
3. **PowerShell 不支持 `&&`**：必须用 `;` 分隔命令，否则报 `The token '&&' is not a valid statement separator`。
4. **Edit 工具跨匹配风险**：当 old_string 跨越中间的函数/接口定义时，可能误替换。需用 `export default function` count 验证和 typecheck 双重确认。
5. **subagent 返回空结果时改用 general_purpose_task**：parallel-sub-agent 偶发返回 "The toolcall result is missing."，改用 general_purpose_task 类型可恢复。
