# S7 后端技术债处理

## 第一章：问题分析

### 问题现象

S6 合流交付后，以下 4 项后端技术债被登记为已知未闭合项，需在 S7 运维阶段处理：

1. **S7-1 claiming 超时回滚缺失**：shop_orders / cdk_codes 表的乐观锁两段事务中，`claiming` 状态无超时回滚机制。若命令发送后崩溃，记录永久卡在 `claiming` 状态。
2. **S7-2 audit_logs 写入未注入**：路由层关键操作（shop claim / cdk redeem）未调用 auditLogService.create，审计日志表无数据。
3. **S7-3 monitorService.checkThreshold 未实现**：接口存根要求 `checkThreshold(serverId, metrics)` 方法，但实现中缺失。
4. **S7-4 webhookService.triggerWebhook 未实现**：接口存根要求 `triggerWebhook(serverId, eventType, payload)` 自动触发链路，但实现中缺失。

### 影响范围

- 乐观锁卡死：订单/CDK 永久不可领取（S7-1）
- 审计追溯缺失：物品发放操作无审计记录（S7-2）
- 监控告警缺失：超阈值无告警（S7-3）
- Webhook 自动通知缺失：业务事件无法自动推送外部系统（S7-4）

### 根因分析

- S7-1：shop_orders / cdk_codes 表无 `claiming_at` 字段记录进入 claiming 的时间，scheduler 未注册 OPTIMISTIC_LOCK_TIMEOUT_SCAN 周期任务
- S7-2：路由层未注入 auditLogService.create 调用
- S7-3：monitorService 仅有 list/create/getLatest，缺 checkThreshold 方法
- S7-4：webhookService 仅有 list/create/update/remove/triggerTest，缺 triggerWebhook 方法 + index.ts 未订阅 eventBus 事件

## 第二章：修复方案

### 方案描述

1. **S7-1**：新增 migration 添加 `claiming_at` 字段；修改 claimOrder/redeem 设置/清空 claiming_at；新增 rollbackStaleClaiming 方法；index.ts 注册周期任务
2. **S7-2**：在 shop.ts claim 和 cdk.ts redeem 路由成功后注入 auditLogService.create（void + .catch 不阻塞主流程）
3. **S7-3**：monitorService 新增 checkThreshold 方法，从 system_config 表读取阈值对比 metrics
4. **S7-4**：webhookService 新增 triggerWebhook + deliverWithRetry（3次重试+指数退避）；index.ts 订阅 eventBus 关键事件

### 替代方案

- S7-1 替代方案：在 shopService/cdkService 内部启动独立定时器（不依赖 scheduler）— 否决理由：与现有 scheduler 架构不一致
- S7-2 替代方案：在 service 层注入 auditLogService — 否决理由：需修改构造函数签名，影响面大
- S7-4 替代方案：在路由层直接调用 triggerWebhook — 否决理由：耦合路由与 webhook，eventBus 订阅更解耦

### 风险评估

- S7-1：migration 已执行成功，claiming_at 字段已添加；rollbackStaleClaiming 使用条件 UPDATE，不影响正常流程
- S7-2：审计日志失败不影响主流程（void + .catch）
- S7-3：system_config 无阈值配置时返回 {alert: false}，不误告警
- S7-4：webhook 投递失败仅 console.warn，全部失败才抛 WebhookDeliveryError
