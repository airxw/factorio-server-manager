# 对比 factorio 项目补齐六大功能差距

## 一、问题分析

### 问题现象

用户要求对比 `d:\代码\factorio` 项目，审视六大核心功能在 gameserver-panel 中的实现完整性。

### 对比分析

| # | 功能 | factorio 实现 | gameserver-panel 当前状态 | 差距 |
|---|------|--------------|-----------------------|------|
| 01 | 玩家加入·欢迎语+礼包 | joinHandler 防抖 + 欢迎语广播（含 VIP 联动）+ 首次礼包 + 回归礼包 + 离开消息 | handlePlayerJoinWelcome 仅下发 first_gift_command | ❌ 缺欢迎语广播、缺离开消息 |
| 02 | 绑定实例·获得 VIP | bindingService + vipService | 完整实现（前端 Profile.tsx 绑定 + VIP 自动匹配 + 商城解锁） | ✅ 无差距 |
| 03 | 商城消费·自动到账 | shopService.claimOrder 同步 Lua 下发 | shopService.claimOrder → commandDispatcher.enqueue → COMMAND_QUEUE_PROCESS 异步下发 | ✅ 无差距（机制不同但等效） |
| 04 | CDK 兑换·额外奖励 | 无独立 CDK 服务，通过 !claim 命令统一处理 | 独立 cdkService.redeemCdk → commandDispatcher.enqueue 下发 | ✅ 无差距（更完善） |
| 05 | 聊天互动·社区活跃 | chatMonitor（含 !verify/!claim/内置命令/自定义规则/冷却）+ periodicMessageService（独立注册到 scheduler） | handleChatTrigger 关键词匹配 + PERIODIC_MESSAGE 调度任务 | ✅ 无差距（机制不同但等效） |
| 06 | 投票自治·共建社区 | voteService 聊天命令触发 + 阈值踢人 + 过期恢复 | voteService.castVote 前端 API 触发 + VOTE_THRESHOLD_MET 自动 kick | ✅ 无差距（机制不同但等效） |

### 根因分析

差距集中在功能 01：
- gameserver-panel 多 pack 架构下，欢迎语和离开消息应通过 pack.commands.broadcast 命令模板渲染下发
- 当前 handlePlayerJoinWelcome 仅实现了礼包下发，未实现欢迎语广播
- 当前未订阅 PLAYER_LEAVE 事件，离开消息广播完全缺失

## 二、修复方案

### 方案选择

**不修改 public/schema/pack-schema.ts**（避免触发 public/ 保护规则），复用所有 5 个 pack 已声明的 `commands.broadcast` 命令模板（如 `say {{message}}` / `broadcast {{message}}`）。

### 修复点

1. **handlePlayerJoinWelcome 扩展**：在 first_gift_command 下发前/后，先用 commands.broadcast 渲染"欢迎玩家 {player} 加入服务器"消息并入队
2. **新增 handlePlayerLeave**：订阅 PLAYER_LEAVE 事件 → 查询 pack.commands.broadcast → 渲染"玩家 {player} 离开服务器"消息 → 入队下发

### 不实现的部分（与 factorio 项目差异）

- **防抖**：gameserver-panel 已用 hasClaimedToday 防礼包重复；欢迎语广播幂等，多次广播影响不大；不实现
- **VIP 专属欢迎语**：需要扩展 schema 添加 vip_welcome_command 字段；当前阶段不实现
- **回归礼包**：需要扩展 schema 添加 relogin_gift_command 字段；当前阶段不实现
- **离开消息广播冷却**：单次广播，无需冷却
