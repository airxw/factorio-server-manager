# 补齐游戏内聊天命令交互能力（对比 factorio 项目）

## 一、问题分析

### 问题现象

用户对比 `d:\代码\factorio` 项目后发现 gameserver-panel 缺失大量"玩家在游戏内通过聊天命令完成"的能力：

1. 玩家绑定只能在 web 完成，无法在游戏控制台 `!verify <验证码>` 完成绑定
2. CDK 兑换只能在 web 完成，无法在游戏内 `!claim <code>` 兑换
3. 投票踢人只能由 web API 触发，玩家无法在游戏内 `!vk <玩家名>` / `!vk yes` / `!vk no` 发起或参与投票
4. 缺失 `!help` / `!status` / `!players` / `!uptime` 等游戏内查询命令
5. 欢迎词配置入口 `PlayerJoinSettings.tsx` 已存在但未真正生效（web 配置表与 `handlePlayerJoinWelcome` 脱节，后者读 pack.yaml 而非 DB 配置表）

### 影响范围

- 模块10（游戏内聊天交互）
- 公共契约：public/schema/pack-schema.ts、public/schema/panel-api-types.ts
- 后端：instanceBindingService、voteService、inGameCommandService（新增）、chatService、index.ts
- 前端：PlayerVerify（新增）、PlayerJoinSettings（修改）、PlayerBindings（新增）、ChatTriggers（修改）
- 数据库：5 个新迁移

### 根因分析

对比 factorio 项目 [chatMonitor.ts](file:///d:/代码/factorio/backend/src/services/chatMonitor.ts) 的 `handleAutoReply` 函数，其内置命令 `!verify`（调用 verifyBinding）和 `!claim`（调用 claimOrder）直接在游戏内聊天事件中处理，与 web 路径并行。

gameserver-panel 现有 `index.ts handleChatTrigger` 仅匹配 `chat_trigger_responses` 表中的自定义关键词，完全不识别任何 `!` 前缀命令。需要新增 `inGameCommandService` 统一解析游戏内命令。

## 二、修复方案

### 方案选择

新增 `inGameCommandService.ts` 作为单点统一命令分发器，订阅 `eventBus.CHAT_EVENT`，按命令优先级分发：
- 内置命令优先级 > 自定义规则匹配
- `!verify/!claim` 不走冷却（关键操作）
- `!help` 走短冷却防刷屏

### 修复点

1. **新增 inGameCommandService**：统一解析 !verify/!claim/!help/!status/!players/!uptime/!vk 七个命令
