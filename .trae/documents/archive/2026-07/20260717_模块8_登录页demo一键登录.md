# 模块8 — 登录页 demo 入口支持一键登录

**日期**：2026-07-17
**模块**：模块8_前端应用
**版本**：3.3.0 → 3.3.3
**类型**：Bug 修复 + UI 调整 + 权限矩阵扩展

---

## 一、问题描述

### 用户反馈
`http://gsp.ecsrz.com:3000/login` 的 demo 登录入口要求手动输入密码，体验不对。

### 根因
原 `Login.tsx` 的 demo 入口（`<code onClick={fillPreset}>`）只做"填表"动作，不自动提交。用户必须：
1. 点击 `admin@local.dev / admin123` 让其填入表单
2. 手动点击「登录」按钮

两次操作对"演示/快捷登录"场景过重。同时原入口仅在 `import.meta.env.DEV === true` 时显示，生产环境（vite build）下完全隐藏，无法满足"内网/受控环境下生产也能演示"的需求。

---

## 二、修复方案

### 2.1 行为升级：点击即登录

将 demo 入口由"填表"改为"自动填表 + 立即提交"，从两步简化为一步。

实现要点：
- 抽出 `doLogin(email, password)` 内部函数，复用校验 → setSubmitting → login() → navigate / 错误处理全流程
- 新增 `useDemoLogin()` 入口：先 setState 同步填入凭据，再 `void doLogin(...)` 触发登录
- demo 元素由 `<code onClick={...}>` 升级为 `<button type="button" className="login-hint-code">`，改善可访问性（键盘焦点 / 屏幕阅读器 / `disabled` 状态）
- 提交中 `submitting === true` 时按钮 `disabled`，避免重复点击

### 2.2 可见性控制：环境变量开关

新增 `VITE_ENABLE_DEMO` 变量控制入口可见性：

```typescript
const showDemoEntry =
  import.meta.env.DEV || import.meta.env.VITE_ENABLE_DEMO === 'true';
```

语义：
- `import.meta.env.DEV === true`（开发/test 模式）：默认展示
- `vite build` 生产模式：默认隐藏，需 `VITE_ENABLE_DEMO=true` 显式开启

安全考量：硬编码的管理员凭据（`admin@local.dev` / `admin123`）在生产构建中通过 Vite dead code elimination 移除——只有 `showDemoEntry` 为 true 时相关字符串才会被打包进 bundle。

### 2.3 环境变量配置

| 文件 | 默认值 | 说明 |
|------|--------|------|
| `.env.example` | `VITE_ENABLE_DEMO=false` | 文档化新变量 |
| `.env` | `VITE_ENABLE_DEMO=false` | 通用默认，关闭 |
| `.env.development` | `VITE_ENABLE_DEMO=true` | 开发模式开启 |
| `.env.production` | `VITE_ENABLE_DEMO=false` | 生产模式关闭 |
