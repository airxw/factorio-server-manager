## 问题诊断详情

### 根因分析

Daemon WS 服务端（`daemon/src/server.ts`）的 `broadcast()` 函数仅向已订阅的 WS 客户端推送事件：

```typescript
function broadcast<T>(instanceId: string, event: T): void {
  const set = subscribersByInstance.get(instanceId);
  if (!set || set.size === 0) return;  // ← 无订阅者则丢弃事件
  ...
}
```

订阅需通过 WS 消息 `{type:'subscribe', instance_id}` 显式注册。但 panel 的 `DaemonEventStream`（`panel/backend/src/daemonClient/eventStream.ts`）连接后只接收事件，从未发送 subscribe 命令。

结果：daemon 检测到 `Done (Xs)!` 就绪模式后发出 `state.change`（starting → running）事件，但 panel 未订阅，事件被丢弃，DB 永远停留在 `starting`。

### 修复方案

1. **`DaemonEventStream.subscribe(instanceId)`**：新增公共方法，WS OPEN 时发送 `{type:'subscribe',instance_id}` 消息
2. **`onConnect` 全量订阅**：`listInstances()` 返回的所有实例逐个 subscribe（覆盖重连场景）
3. **`onInstanceStart` 启动时订阅**：`POST /:id/start` 成功后立即订阅新实例（覆盖首次启动场景）
4. **引用持有者模式**：`daemonEventStreamRef` 解决 `daemonEventStream` 在路由之后才创建的时序问题
