# 修复配置文件读取报错 + 实现游戏服务端自动更新

## 一、问题分析

### 问题现象

用户反馈两个问题：

1. **版本控制与更新按钮缺失**：
   - 实例中的 Pack 和游戏服务端版本控制机制不清楚
   - 实例详情页缺少"一键更新/下载服务端版本"按钮

2. **游戏配置文件不可见**：
   - 以 Factorio 为例，配置文件 tab 显示"暂无配置文件"或内容为空
   - 实际验证 ConfigFileEditor 加载配置文件时报错：`Instance not found: <serverId>`

### 影响范围

- 所有游戏 Pack 的实例详情页
- 用户无法查看/编辑游戏配置文件
- 用户无法更新游戏服务端版本

### 根因分析

#### 根因 1：Pack YAML 未声明 `update` tab

- 所有 5 个 Pack 的 `ui.tabs` 缺少 `- update` 项
- `InstanceTabSchema` zod enum 缺少 `'update'` 值
- → ServerDetail.tsx 的 tabs 数组中不含 `'update'`，"游戏更新" tab 不显示
- **已修复**：在 InstanceTabSchema enum 添加 `'update'`，5 个 Pack 的 ui.tabs 添加 `- update`

#### 根因 2：daemon 端实例未注册

- `daemon/src/instances/manager.ts` 的 `managed: Map<string, ManagedInstance>` 仅在 `startInstance` 时注册
- 实例从未启动过 → daemon 端没有该实例的 workdir 信息
- `daemon/src/server.ts` 的 `GET /api/instances/:id/files/read` 在 `manager.getInstance(id)` 返回 undefined 时报 `INSTANCE_NOT_FOUND`
- → `configFileService.readConfigFile` 调用 daemon readFile 报错 → ConfigFileEditor 显示 "Instance not found"

#### 根因 3：配置文件未生成

- 即便修复根因 2，如果 workdir 中的配置文件不存在（如 `config/server-settings.json`），daemon 会报 `FILE_NOT_FOUND`
- Factorio Pack 声明 `config_files[].path = '{{config_dir}}/server-settings.json'`，但该文件需要 bootstrap 或游戏服务端首次运行时生成
- → 需要让 readConfigFile 在文件不存在时返回空对象，让用户可以编辑后保存

#### 根因 4：updateService.applyUpdate 是手动模式

- 当前 `applyUpdate(serverId, downloadPath)` 要求调用方提供已下载文件的绝对路径
- 前端 UpdateCheck.tsx 是 P0 简化模式（用户手动下载文件 → 填路径 → 应用）
- 用户要求升级为"实现自动下载"：daemon 根据 Pack.update.source_url 自动下载最新版本并安装
- → 需要扩展后端新增 `downloadUpdate` 方法 + 前端新增"一键下载并安装"按钮

## 二、修复方案

### 方案 A：daemon 端 readFile/writeFile 兼容未注册实例

- 修改 `daemon/src/server.ts` 的 `GET /api/instances/:id/files/read` 和 `PUT /api/instances/:id/files`
- 如果 `manager.getInstance(id)` 返回 undefined，则从 `INSTANCES_DIR` 环境变量推断 workdir（`<INSTANCES_DIR>/<id>`）
- 自动 mkdir -p 创建 workdir（如果不存在）
- 这样未启动的实例也能读写配置文件

### 方案 B：configFileService.readConfigFile 文件不存在时返回空对象

- 修改 `panel/backend/src/services/configFileService.ts`
- 捕获 `FILE_NOT_FOUND` 错误，返回空对象 `{}`
- 用户能在 ConfigFileEditor 看到空配置，编辑后保存（保存时通过 daemon writeFile 创建文件）

### 方案 C：扩展 updateService 实现自动下载

- 在 `updateService.ts` 新增 `downloadUpdate(serverId)` 方法
- 流程：
  1. 调用 `checkUpdate(serverId)` 获取 `latest_version`
  2. 根据 Pack.versions.download_pattern 渲染下载 URL（或用 source_url 直接下载）
  3. 通过 daemon `execCommand` 执行下载命令（`curl -L -o {{download_path}} <url>`）
  4. 调用 `applyUpdate(serverId, downloadPath)` 执行 install_command
- 后端新增路由 `POST /api/servers/:serverId/update/download`
- 前端 UpdateCheck.tsx 升级为"一键下载并安装"模式

### 风险评估

- 方案 A：低风险。仅在 file ops 路径添加兜底，不影响 startInstance 流程
- 方案 B：低风险。仅修改 readConfigFile 的错误处理
- 方案 C：中风险。需要 daemon 执行外部下载命令，需要考虑网络超时、磁盘空间、校验等问题。P0 简化：仅支持 source_url 直接下载，不做 checksum 校验

### 已知限制（P0 简化）

1. **curl 依赖**：自动下载要求 daemon 节点预装 curl
2. **无 checksum 校验**：下载后不校验文件完整性
3. **无进度显示**：前端用文字提示"下载并安装中…（请耐心等待）"，无实时进度条
4. **下载超时 10 分钟**：大文件可能超时（Factorio headless ~100MB）
5. **current_version 未知时无法比对**：实例未启动时 current_version=null，无法精确判断是否需要更新，统一视为"有更新可下载"
