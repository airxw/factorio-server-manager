# v4.13.0 角色门控审计清单（实例详情页拆分续篇）

## 一、审计范围

承接 v4.12.0 角色门控审计的"待 v4.13.0 处理项"，对 v4.13.0 新增的三套实例详情视图路由门控进行逐项审计，确认 `/instances/:id` 拆分后门控已上提到路由层，无权限放大。

## 二、三套实例详情视图门控（v4.13.0 新增）

| 视图 | 路径 | 组件 | 门控配置 | 角色范围 | 评估 |
|------|------|------|---------|---------|------|
| 系统管理员视图 | `/admin/servers/:id` | ServerDetailAdmin | `['server_admin', 'system_admin', 'admin']`（继承 `/admin` 基座） | 系统管理员 | ✅ 符合方案 §8 |
| 服主视图 | `/store/servers/:id` | ServerDetailStore | `['instance_admin', 'server_admin', 'system_admin', 'admin']`（继承 `/store` 基座） | 服主（含越级） | ✅ 符合方案 §9 |
| 玩家视图 | `/guild/servers/:id` | ServerDetailGuild | `ProtectedRoute`（user+，继承 `/guild` 基座） | 所有已登录用户 | ✅ 符合方案 §10 |

### 2.1 三套视图懒加载（rules-0 §3.1.1 路由结构守卫）

- `App.tsx:111-113` 三组件均通过 `React.lazy` 导入
- `<Suspense>` 位于共享 `Layout.tsx` 内包裹 `<Outlet />`（line 722-731 / 981-990），未直接置于 `<Route>` 下
- `<Routes>` 直接子元素全为 `<Route>` 或 `<React.Fragment>`，无违规嵌套

### 2.2 旧 `/instances/:id` 重定向（向后兼容）

`App.tsx:226-235` `InstanceDetailRoleRedirect` 按角色重定向：
- `server_admin` → `/admin/servers/:id`
- `instance_admin` → `/store/servers/:id`
- `user` → `/guild/servers/:id`

`App.tsx:240-246` `InstanceListRoleRedirect` 对 `/instances` 列表同样按角色重定向到 `/admin/servers` / `/store/servers` / `/guild`。

### 2.3 旧 `/instances/:id/*` 子路径保留

以下子路径暂保留在旧 Layout 下（组件内部已有角色门控兜底），向后兼容外部链接：

| 路径 | 组件 | 当前门控 | 备注 |
|------|------|---------|------|
| `/instances/:id/shop` | Shop | user+ | 消费侧，user+ 合理 |
| `/instances/:id/shop-orders` | ShopOrders | user+ | 消费侧，user+ 合理 |
| `/instances/:id/cdk-redeem` | CdkRedeem | user+ | 消费侧，user+ 合理 |
| `/instances/:id/business` | Business | user+（内部 admin 校验） | 服主功能，内部组件门控兜底 |
| `/instances/:id/player-histories` | PlayerHistories | user+ | 系统监控类，内部组件门控兜底 |
| `/instances/:id/gift-claims` | GiftClaims | user+ | 消费侧，user+ 合理 |

**风险评估**：旧子路径的门控上提未在 v4.13.0 完成，依赖内部组件门控兜底。由于 `RootRedirect` 已确保 user 登录后直接进入 `/guild`，不会主动访问 `/instances`，且 `InstanceDetailRoleRedirect` 已将 `/instances/:id` 主路径重定向到三套视图，残留子路径不构成越权风险。建议 v4.14.0 将这些子路径也按角色重定向到对应视图的子 Tab。

## 三、新增后端 API 路由门控（v4.13.0 阶段三）

### 3.1 GM Workbench 后端 API（`/api/store/*`）

| 端点 | 路由文件 | 门控 | 备注 |
|------|---------|------|------|
| `GET /api/store/players` | store-gm.ts:108 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` | 玩家列表（CRM） |
| `GET /api/store/reports/revenue` | store-gm.ts:241 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` | 流水报表 |
| `GET /api/store/reports/playtime` | store-gm.ts:329 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` | 时长统计 |
| `GET /api/store/servers` | store-gm.ts:417 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` | 服主实例列表 |
| `POST /api/store/players/:userId/compensate` | store-player-actions.ts:96 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` + `authorizeInstanceAccess` | 发放补偿 |
| `POST /api/store/players/:userId/ban` | store-player-actions.ts:174 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` + `authorizeInstanceAccess` | 封禁玩家 |
| `POST /api/store/players/:userId/adjust-playtime` | store-player-actions.ts:242 | `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` + `authorizeInstanceAccess` | 调整时长 |

**`authorizeInstanceAccess` 细粒度门控**（store-player-actions.ts:356-380 / store-gm.ts:501-535）：
- `server_admin` / `system_admin` / `admin` → 直接通过（越级查看）
- `instance_admin` → 校验 `owner_user_id = 当前用户`，否则 403
- `user` → 403（非管理员不可访问 GM Workbench API）

### 3.2 实例店铺外观配置（`/api/store/servers/:serverId/shop-config`）

| 端点 | 路由文件 | 门控 | 备注 |
|------|---------|------|------|
| `GET /api/store/servers/:serverId/shop-config` | store_shop_config.ts:45 | `requireInstanceAccess`（user+ 拥有实例访问权即可读） | 玩家可读店铺配置 |
| `PUT /api/store/servers/:serverId/shop-config` | store_shop_config.ts:61 | `requireInstanceAdmin`（instance_admin+ 服主才能改） | 仅服主可改 |

### 3.3 Daemon 上报端点（`/api/daemon/*`）

| 端点 | 路由文件 | 门控 | 备注 |
|------|---------|------|------|
| `POST /api/daemon/player-sessions/join` | daemon-report.ts:79 | `x-report-key` 头校验（DAEMON_REPORT_KEY） | daemon 上报玩家加入 |
| `POST /api/daemon/player-sessions/leave` | daemon-report.ts:164 | `x-report-key` 头校验（DAEMON_REPORT_KEY） | daemon 上报玩家离开 |

**鉴权方式**：daemon 上报端点不使用 JWT，而使用 `DAEMON_REPORT_KEY` 共享密钥（配置于 `public/config_template/{daemon,panel}.env.template`）。未配置时返回 403，密钥不匹配返回 401。

## 四、审计结论

### 4.1 已闭合项

- 三套实例详情视图门控上提到路由层 ✅
- `/instances/:id` 主路径按角色重定向到三套视图 ✅
- `/instances` 列表按角色重定向 ✅
- GM Workbench 后端 API 全部 `requireRole(INSTANCE_ADMIN, SERVER_ADMIN)` ✅
- 玩家操作 API 额外 `authorizeInstanceAccess` 细粒度门控 ✅
- 实例店铺配置读写门控分离（读 user+ / 写 instance_admin+）✅
- Daemon 上报端点使用共享密钥鉴权 ✅
- 三套视图懒加载 + Suspense 放置合规（rules-0 §3.1.1）✅

### 4.2 待 v4.14.0 处理项（不阻断 v4.13.0 闭合）

- `/instances/:id/*` 子路径（shop/shop-orders/cdk-redeem/business/player-histories/gift-claims）暂保留在旧 Layout 下，未按角色重定向到对应视图的子 Tab
- 不阻断理由：
  1. `RootRedirect` 已确保 user 登录后直接进入 `/guild`
  2. `InstanceDetailRoleRedirect` 已将 `/instances/:id` 主路径重定向到三套视图
  3. 残留子路径的组件内部有角色门控兜底
  4. 外部链接向后兼容（方案 §五 声明保留期至 v4.14.0）
