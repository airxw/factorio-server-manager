# v4.13.0 public/ 契约变更授权记录与设计偏离说明

## 一、授权背景

v4.13.0 方案 `docs/plans/v4.13.0-instances-split-plan.md` 步骤1-2 明确要求扩展 Instance_Assets 契约，新增 `banner_url` / `banner_link` / `shop_description` / `shop_theme_color` 4 字段，属 `public/` 受保护路径变更，需走 s0601 流程 + ec7_action_gate 拦截 + 人类显式授权。

**授权依据**：人类在会话中裁决"批准执行+授权契约变更"（合并 Pack 重构与实例拆分到 v4.13.0 一起部署）。计划级授权已存在，本文件记录实际执行时的具体变更范围与设计偏离。

## 二、授权范围（实际执行）

### 2.1 `public/schema/panel-api-types.ts` 变更

**变更类型**：增量新增（未删除/修改/覆盖既有契约）

## 三、设计偏离说明（GN-004 警示项 1）

### 3.1 方案原文 vs 实际实现

| 维度 | 方案原文（步骤2-7） | 实际实现 | 偏离理由 |
|------|-------------------|---------|---------|
| 数据表 | 扩展 `instance_assets` 表加 4 字段 | 新建 `instance_shop_configs` 表（一实例一行） | 店铺外观属实例级配置，与资产级 override 字段解耦，避免冗余存储 |
| 后端 Service | 扩展 `AssetService` CRUD | 新建 `InstanceShopConfigService` | 职责单一，店铺配置与资产管理分离 |
| 前端 API 模块 | 扩展 `api/modules/asset.ts` | 新建 `api/modules/shop-config.ts` | 与后端 Service 对应 |
| Migration | `add_instance_assets_shop_fields` | `20260806000001_create_instance_shop_configs` | 新建表而非改既有表 |

### 3.2 偏离评估

- **契约意图保留**：4 字段（`banner_url` / `banner_link` / `shop_description` / `shop_theme_color`）全部保留，类型与可空性与方案一致 ✅
- **向后兼容**：新建表 + 新增接口，未破坏既有 `instance_assets` 契约 ✅
- **运行时接入**：`InstanceShopConfigService` 已在 `services-init.ts:274/329` 注入，路由已在 `routes-registry.ts:721` 挂载 ✅
- **风险等级**：低（增量型变更，无破坏性）

### 3.3 后续维护指引

后续维护者查找店铺外观配置实现时：
- 数据表：`instance_shop_configs`（非 `instance_assets`）
- 后端 Service：`InstanceShopConfigService`（非 `AssetService`）
- 后端路由：`store_shop_config.ts`（非 `assets.ts`）
- 前端 API：`api/modules/shop-config.ts`（非 `api/modules/asset.ts`）
- 前端类型：`InstanceShopConfig`（非 `GlobalAssetDto` / `InstanceAssetDto`）
