# 系统诊断全量检查项改造方案

## 一、背景与目标

当前系统诊断（`/admin/diagnostics`）仅展示检测到的问题项，无法直观了解哪些检查项已通过。用户希望诊断页面能展示**所有检查项的完整状态**，清晰区分：
- ✅ 通过的检查项
- ⚠️ 警告项
- ❌ 错误项

## 二、开发事项

### 2.1 后端改造：DiagnosticsResult 增加全量检查项

- 在返回结构中新增 `checks` 字段，包含所有检查项的完整结果
- 每个检查项包含：`id`、`title`、`category`、`status`（pass/warning/error）、`message`、`severity`、`fixable`、`fixId`
- 保留原有 `problems` 字段以确保向后兼容
- 修改 `runRule` 返回结构，增加状态标识（不再仅返回 problem/null）

### 2.2 后端改造：扩展诊断规则配置

新增以下检查类别和检查项：

**系统环境类**
- 磁盘使用率
- 内存使用率（新增）
- Node.js 版本（新增）
- 系统运行时间（新增）

**服务状态类**
- Panel 后端进程
- Daemon 进程（新增）
- 数据库连通性
- Daemon 端口监听（新增）

**游戏依赖类**
- Java 运行环境（新增，检测 java 命令及版本）
- SteamCMD 安装状态（新增，检测 /opt/steamcmd/steamcmd.sh）
- SteamCMD 32位依赖库（新增）

**配置完整性类**
- Pack 配置目录存在性（新增）
- 诊断规则配置文件存在性（新增）

### 2.3 后端改造：新增检查类型实现

- `memory_usage`：内存使用率检查
- `command_exists`：命令存在性检查（用于 java、steamcmd 等）
- `java_version`：Java 版本检查
- `steamcmd_check`：SteamCMD 完整性检查
- `directory_exists`：目录存在性检查

### 2.4 前端改造：诊断页面重构

- 页面顶部展示汇总信息：总检查项数、通过数、警告数、错误数
- 按类别分组展示所有检查项（系统环境、服务状态、游戏依赖、配置完整性）
- 每个检查项用图标+颜色区分状态：
  - ✅ 绿色：通过
  - ⚠️ 黄色：警告
  - ❌ 红色：错误
- 可展开查看详细描述和修复建议
- 保留"一键修复"功能（仅异常且可修复的项显示）
- 保留"复制报告"功能（包含全部检查项）
- 增加"仅显示问题"切换开关

### 2.5 前端 API 类型更新

- 扩展 `DiagnosticCheck` 接口定义
- 扩展 `DiagnosticsResult` 接口，增加 `checks` 字段
- 保持 `DiagnosticProblem` 接口不变以兼容

## 三、配置文件变更

- 更新 `modules/模块12_系统诊断/config/diagnostic-rules.json`，新增上述检查项
- 保持现有规则的向后兼容性

## 四、接口兼容性

- 新增字段不影响现有调用方
- 原有 `problems` 字段继续返回（仅包含异常项）
- 新增 `checks` 字段包含全量检查结果

## 五、建议

1. 建议在页面增加"自动刷新"功能，定时刷新诊断结果
2. 建议后续增加"诊断历史记录"功能，方便追踪问题演变
3. 建议将 SteamCMD 安装检查加入部署脚本自动执行
4. 建议为每个检查项增加"详细帮助"链接，指向对应文档
