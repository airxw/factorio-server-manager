## 五、回退锚点

### 5.1 阶段 A 回退
- **回退点**：契约文件落地前的 git commit
- **回退动作**：`git checkout -- public/`
- **风险**：无（public/ 未变更前无可污染下游）

### 5.2 阶段 B 回退
- **回退点**：迁移脚本执行前的 SQL dump 备份
- **回退动作**：
  1. 停服（deploy.sh stop）
  2. `sqlite3 panel.db < backup.sql`（恢复旧三套表 + 旧 users schema）
  3. `git checkout -- panel/backend/src/db/migrations/ panel/backend/src/core/auth/ panel/backend/src/middleware/auth.ts panel/backend/src/services/userService.ts`
  4. 重启服务
- **风险**：迁移后若有用户在新 schema 上产生数据，回退会丢失这部分数据 → 必须在低峰期窗口操作

### 5.3 阶段 C/D 回退
- **回退点**：阶段 B 完成后的 git commit
- **回退动作**：`git revert` 实现层 commit，保留契约与迁移脚本
- **风险**：仅功能回退，无数据风险

### 5.4 阶段 E 回退
- **回退点**：部署前 git commit + 生产备份
- **回退动作**：deploy.sh rollback
- **风险**：低（标准回滚流程）
