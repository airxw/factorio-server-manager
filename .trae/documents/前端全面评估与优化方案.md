## 二、功能缺陷评估

### 2.1 高优先级缺陷

| 编号 | 问题描述 | 影响范围 | 根因分析 |
|------|---------|---------|---------|
| F-001 | **路由层无权限守卫** | 所有管理后台路由 | 仅在菜单层隐藏菜单项，但路由层无校验，用户可直接通过 URL 访问管理页面，如 `/admin/users`、`/admin/system-config` 等 |
| F-002 | **列表无分页机制** | 所有列表页（用户/服务器/审计日志等） | 全量加载数据，数据量大时性能极差 |
| F-003 | **API 客户端重复实现** | API 层 | 存在两套 API 实现：`createApiClient` 工厂 + 独立 fetch 函数（`listMyBindings`、`bindInstance`、`unbindInstance`、`listInstanceBindings`、`updateBindingVip`、`reloadPacks` 等），维护成本高 |
| F-004 | **控制台日志无上限** | RCON 控制台 | `displayLines` 数组无限增长，长时间运行后内存占用过高 |

**F-001 详情**：
- 位置：[App.tsx](file:///home/airxw/Documents/gsp/gameserver-panel/panel/frontend/src/App.tsx#L111-L160)
- 现状：`/admin/* 路由均在 ProtectedRoute 内，仅检查登录状态，未检查角色
- 风险：普通用户可通过直接访问 URL 进入管理页面（虽然后端会返回 403，但前端应先拦截）

**F-003 详情**：
- 位置：[client.ts](file:///home/airxw/Documents/gsp/gameserver-panel/panel/frontend/src/api/client.ts#L1190-L1329)
- 重复的 API：`listMyBindings`、`bindInstance`、`unbindInstance`、`listInstanceBindings`、`updateBindingVip`、`reloadPacks`
- 问题：错误处理不统一、鉴权逻辑重复、无 401 自动登出

## 三、性能问题评估

### 3.1 高优先级性能问题

| 编号 | 问题描述 | 影响程度 | 根因分析 |
|------|---------|----------|---------|
| P-001 | **控制台日志无虚拟化** | 🔴 严重 | `displayLines` 数组无上限，DOM 节点无限增长，1000+ 行后渲染卡顿 |
| P-002 | **列表全量加载** | 🔴 严重 | 无分页，大数据量下首屏加载慢、渲染卡 |
| P-003 | **无请求缓存/去重** | 🟡 中等 | 相同 API 在不同组件重复调用，浪费带宽和服务器资源 |

**P-001 详情**：
- 位置：[RconConsole.tsx](file:///home/airxw/Documents/gsp/gameserver-panel/panel/frontend/src/components/RconConsole.tsx#L39)
- 现状：`displayLines` 无限追加，无截断机制
- 影响：长时间运行的实例（数小时后）日志可达数万行，浏览器内存占用数 GB 级

**P-003 详情**：
- 位置：多个组件调用相同 API，如 `listServers` 在 Dashboard、Servers、ServerDetail 中均可能调用
- 无缓存层，每次进入页面都重新请求

### 3.2 中优先级性能问题

| 编号 | 问题描述 | 影响程度 | 根因分析 |
|------|---------|----------|---------|
| P-004 | 无路由懒加载 | 🟡 中等 | 所有页面打包进单个 chunk，首屏加载体积大 |
| P-005 | 无数据获取库 | 🟡 中等 | 手写 useEffect + useState 模式，无缓存/重试/后台刷新 |
| P-006 | 单 CSS 文件无按需加载 | 🟢 轻微 | 全局 700+ 行 CSS 全部加载 |
| P-007 | 无请求取消机制 | 🟢 轻微 | 组件卸载后请求仍在进行，可能导致状态更新警告 |

### 3.3 性能优化建议汇总

| 优化项 | 预期收益 | 实施难度 |
|--------|---------|---------|
| 控制台日志虚拟化 + 环形缓冲 | 内存占用降低 80%+ | 中 |
| React Query 引入 + 请求缓存 | 重复请求减少 50%+ | 中 |
| 路由懒加载 + 代码分割 | 首屏 JS 体积减少 60%+ | 低 |
| 列表分页支持 | 大数据量下渲染性能提升显著 | 高（需后端配合） |
| 图片懒加载 | 图片多的页面加载更快 | 低 |

### 阶段二：架构升级（P0 - 高优先级）

#### 7.5 引入 React Query（TanStack Query）

**技术方案**：
- 替代手写的 `useEffect + useState` 数据获取模式
- 提供缓存、重试、后台刷新、请求去重、乐观更新等能力
- 与现有 `createApiClient` 集成
- 按领域拆分 query hooks

**实施步骤**：
1. 安装 `@tanstack/react-query` 和 `@tanstack/react-query-devtools`
2. 创建 `src/api/queries/` 目录
3. 按领域拆分 query hooks（auth、servers、admin 等）
4. 在 App 顶层添加 QueryClientProvider
5. 逐步迁移各页面数据获取逻辑
6. 保留乐观更新能力

**目录规划**：
```
src/api/
├── client.ts          # 基础请求封装（不变）
└── queries/           # React Query hooks
    ├── auth.ts
    ├── servers.ts
    ├── admin.ts
    └── index.ts
```

**预期效果**：
- 自动缓存减少 50%+ 重复请求
- 统一的加载/错误状态管理
- 支持后台刷新、分页预取、乐观更新

| 通用组件抽象过度设计 | 中 | 中 | 先抽象最常用的 3-5 个，后续按需扩展 |
