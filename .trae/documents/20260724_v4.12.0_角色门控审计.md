## 四、审计结论

### 4.1 已闭合项

- 三基座门控上提完成：`/admin` (server_admin+)、`/store` (instance_admin+)、`/guild` (user+) ✅
- 子路由门控无权限放大：所有子路由门控与基座门控一致或更严 ✅
- 角色跳转闭合：`RootRedirect` 按 `server_admin → /admin`、`instance_admin → /store`、`user → /guild` 跳转 ✅
- 旧路径重定向保留：`/dashboard → /admin`、`/admin/commercial → /store/commercial` 等 ✅

### 4.2 待 v4.13.0 处理项（不阻断 v4.12.0 闭合）

- `/instances/*` 路由层门控未上提：当前为 user+，应拆分为三套视图并按角色门控
- `/instances/:id/business` 路由层门控未提升至 instance_admin+（依赖内部组件门控兜底）
- `/instances/:id/player-histories` 路由层门控未提升至 server_admin+（依赖内部组件门控兜底）

**不阻断理由**：
1. `RootRedirect` 已确保 user 角色登录后直接进入 `/guild`，不会主动访问 `/instances`
2. 残留旧路由的子 Tab 内部有组件级门控兜底，不会导致越权数据泄露
3. `/instances/:id` 拆分为三套视图是独立的大规模重构，超出 v4.12.0 范围（方案 §五 已声明边界）

### 4.3 跨角色访问策略

按方案 §28：跨角色访问统一采用"跳回对应基座 + Toast 提示"策略。当前实现：
- user 访问 `/admin` 或 `/store` → `RequireRole` 重定向到 `/forbidden`
- instance_admin 访问 `/admin` → `RequireRole` 重定向到 `/forbidden`
- server_admin 访问 `/store` → 允许（越级查看，方案 §28 明确允许）
