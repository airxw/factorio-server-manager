# Factorio Server Manager 移动端 UI 显示效果优化方案

> 版本：v1.0  
> 范围：前端 `span`、`div`、`aside` 等核心 UI 元素的视觉、布局与交互  
> 约束：本文档为方案设计，不涉及实际代码修改  

---

## 1. 问题分析

### 1.1 当前界面结构概述

系统采用典型的"侧边栏 + 顶部栏 + 主内容区"三段式布局：

- `aside.sidebar`：左侧导航栏，包含 3 个分组、共 8 个导航项。
- `header.topbar`：顶部操作栏，包含版本检查、版本号、用户名、退出登录。
- `main.main-content`：主内容区，承载仪表盘、实例列表、实例详情、配置等页面。
- `span.badge`：状态徽章，广泛用于实例卡片、实例详情头部（如"运行中""默认""启用"等）。
- `div` 容器：卡片（`.card`）、统计网格（`.stat-grid`）、表单行（`.form-row`）、表格包裹层（`.table-wrap`）等。

当前已在 `index.css` 中通过 `@media (max-width: 768px)` 与 `@media (max-width: 480px)` 实现了一部分移动端适配，例如将侧边栏转为底部导航、调整内边距、单列化部分网格等。

### 1.2 移动端现存主要问题

| 问题类别 | 具体表现 | 影响 |
|---------|---------|------|
| **顶部栏缺失** | `@media (max-width: 768px)` 中 `.topbar { display: none; }` 导致移动端完全看不到版本号、检查更新、用户名、退出登录入口。 | 用户无法查看版本、无法主动退出、无法触发更新。 |
| **底部导航拥挤** | 8 个导航项全部挤在底部固定栏，标签文字被压缩到 9–10 px，图标与文字间距过小，分组标题消失后辨识度下降。 | 容易误触、视觉拥挤、可访问性差。 |
| **状态徽章不协调** | `.badge` 在移动端未调整尺寸，仍保持 11 px 大写英文样式与固定 padding；多个徽章并排时（如实例详情标题行"默认 + 运行中"）容易折行或溢出。 | 信息层级混乱，标题行高度不稳定。 |
| **实例详情头部堆叠** | `.instance-header-row` 在移动端折行后，标题、徽章、操作按钮的顺序与间距未做专门优化；操作按钮（btn-sm，32 px 高）在密集区域偏小。 | 核心操作难以快速定位，拇指操作易误点。 |
| **标签页仅显示图标** | 实例详情页标签在移动端隐藏文字（`.instance-tab span { display: none; }`），对不熟悉的用户认知负担大。 | 用户难以区分"配置""存档""Mod"等标签。 |
| **配置页无移动端适配** | `.config-layout` 采用 240 px 固定左侧边栏，无对应断点样式，小屏幕下会出现横向滚动或内容被挤压。 | 配置页在手机上基本不可用。 |
| **表格横向滚动体验生硬** | `.table-wrap` 设置 `min-width: 600px`，在 375 px 设备上需要大幅横滑，且表头固定后滚动条位置与行对齐感差。 | 数据查看效率低。 |
| **表单标签可读性差** | `.form-label` 使用 12 px 大写 + 0.6 px 字间距，在移动端小屏上显得过细过密。 | 填写表单时标签辨识度不足。 |
| **卡片阴影与边框过重** | 深色主题下多层阴影和 1 px 边框在小屏幕上叠加，显得压抑；卡片内边距从 24 px 降到 16 px 仍显紧张。 | 视觉负担重，信息密度过高。 |
| **动画与手势缺失** | 当前缺少针对移动端的滑动手势（如侧滑返回、底部栏左右滑动切换）、底部安全区适配、点击态反馈优化。 | 操作体验不像原生应用，流畅度不足。 |

### 1.3 问题根因

1. **适配策略以"压缩"为主**：现有媒体查询大多通过缩小字号、隐藏元素、减少内边距来适配小屏，但未针对拇指操作、单手使用、信息优先级重新设计。
2. **缺少移动优先的组件规范**：徽章、按钮、标签页、表单等组件没有独立的移动端变体，导致桌面样式直接缩放。
3. **布局容器未按优先级重排**：实例详情头部、配置页等复杂布局未在小屏幕下进行 DOM 顺序或视觉优先级的调整。
4. **顶部功能栏被整体移除**：为了节省空间直接隐藏，而没有设计替代入口（如汉堡菜单、个人中心浮层）。
5. **缺乏可访问性考量**：最小触控区域、对比度、焦点状态、屏幕阅读器语义未在移动端专门校验。

## 2. 优化目标

### 2.1 总体目标

在不改变当前功能逻辑的前提下，将现有 Web 后台管理界面升级为"桌面完整、移动可用、小屏好用"的响应式体验，使管理员在手机上也能安全、高效地完成实例监控、启停、配置查看与基础管理操作。

### 2.2 具体目标

| 目标编号 | 目标描述 | 衡量标准 |
|---------|---------|---------|
| G1 | 提升视觉美观度与一致性 | 所有组件在移动端有统一的设计语言，色彩、圆角、阴影、间距一致 |
| G2 | 优化屏幕空间利用率 | 在小屏设备（375–414 px 宽）上无横向溢出，关键信息一屏可见 |
| G3 | 改进操作逻辑与交互体验 | 核心操作可在拇指范围内完成，误触率降低，操作反馈明确 |
| G4 | 保证可访问性 | 关键触控目标 ≥ 44×44 px，文字对比度符合 WCAG AA，支持屏幕阅读器 |
| G5 | 保留桌面端体验 | 桌面端布局与交互不受影响，媒体查询边界清晰 |

## 3. 设计规范

### 3.1 适配断点与设备分级

沿用现有断点并补充说明，推荐采用以下三级策略：

| 断点 | 设备类型 | 设计方向 |
|------|---------|---------|
| `>= 1025 px` | 桌面端 / 大屏平板 | 完整侧边栏 + 顶部栏，多列布局，信息平铺 |
| `769 px ~ 1024 px` | 平板 / 折叠屏展开态 | 可保留侧边栏或折叠为图标栏，适度两列 |
| `<= 768 px` | 手机竖屏 / 小屏 | 底部导航 + 精简顶部栏，单列，组件移动化 |
| `<= 480 px` | 小屏手机（如 iPhone SE、Android 小屏机） | 极限空间优化，进一步压缩非关键信息 |

> 建议增加 `375 px` 作为极端小屏的验证基准，但不新增 CSS 断点，通过弹性布局与流式间距兼容。

### 3.2 移动端设计 tokens

在现有 CSS 变量基础上，为移动端场景补充或覆盖以下 token：

```css
:root {
  /* 新增：移动端专用间距 token */
  --mobile-space-xs: 4px;
  --mobile-space-sm: 8px;
  --mobile-space-md: 12px;
  --mobile-space-lg: 16px;
  --mobile-space-xl: 20px;

  /* 新增：移动端圆角（更小，减少视觉扩张感） */
  --mobile-radius-sm: 4px;
  --mobile-radius-md: 6px;
  --mobile-radius-lg: 10px;

  /* 新增：移动端阴影（更柔和、更接近表面） */
  --mobile-shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.2);
  --mobile-shadow-md: 0 2px 6px rgba(0, 0, 0, 0.25);

  /* 新增：底部导航高度与安全区 */
  --bottom-nav-height: 64px;
  --safe-area-bottom: env(safe-area-inset-bottom, 0px);
}
```

### 3.3 字体规范

移动端应遵循更清晰、略大的字号梯度，避免过度使用 11–12 px：

| 元素 | 桌面端 | 移动端建议 | 说明 |
|------|--------|-----------|------|
| 页面标题 | 24 px | 20 px | 保持存在感但不过大 |
| 卡片标题 | 16 px | 15 px | 略微缩小 |
| 正文 | 14 px | 14 px | 保持可读性，不缩小 |
| 辅助说明 | 13 px | 13 px | 可保持 |
| 表单标签 | 12 px 大写 | 13 px 正常大小写 | 提升可读性 |
| 底部导航标签 | 14 px | 11 px | 最小可读字号，配合图标 |
| 徽章文字 | 11 px 大写 | 11 px 正常大小写 | 中文环境下大写不适用，改为常规字重 |

### 3.4 色彩与语义

沿用现有工业科技风深色主题，但移动端做以下微调：

- **减少发光效果**：`.badge-success` 的 `pulse-glow` 动画在移动端应减弱或移除，避免在小屏幕上过于抢眼。
- **状态色增强对比**：确保徽章文字与背景对比度 ≥ 4.5:1，例如 `badge-success` 当前 `#4ade80` 在 `rgba(34,197,94,0.12)` 上对比度足够，但需在所有徽章上统一校验。
- **点击态反馈**：为所有可点击元素增加 `:active` 态的亮度/透明度变化，替代桌面端的 `transform: translateY(1px)`，因为在移动浏览器中 transform 反馈不够明显。

### 3.5 间距规范

| 场景 | 桌面端 | 移动端 |
|------|--------|--------|
| 主内容区内边距 | 32 px 36 px | 16 px |
| 卡片内边距 | 24 px | 16 px（小屏 12 px） |
| 卡片间距 | 20 px | 12 px |
| 表单字段间距 | 16 px | 12 px |
| 按钮组间距 | 10 px | 8 px |
| 列表项间距 | 12 px | 10 px |

## 4. 布局调整策略

### 4.1 全局布局：底部导航 + 精简顶部栏

#### 当前问题

移动端直接隐藏 `.topbar`，导致版本、用户、退出功能完全不可达。

#### 优化策略

1. **保留一个精简版顶部栏**：高度 44 px，仅显示：
   - 左侧：页面标题或当前实例名（动态）。
   - 右侧：用户头像/首字母 + 汉堡菜单按钮。
2. **汉堡菜单浮层**：点击后弹出包含"检查更新""版本信息""个人资料""退出登录"的抽屉或操作表（Action Sheet）。
3. **底部导航栏优化**：
   - 将 8 个入口按优先级分为"常用 4 项 + 更多"：
     - 常用：控制台、实例、商城、设置。
     - 更多：我的订单、个人资料、用户管理、购物权限。
   - 常用项直接显示在底部栏；"更多"点击后展开为底部浮层面板或抽屉。
   - 底部导航项触控区域 ≥ 48×48 px，标签与图标垂直排列，当前项使用图标着色 + 顶部短横线指示器。
4. **安全区适配**：底部导航增加 `padding-bottom: env(safe-area-inset-bottom)`，避免 iPhone 底部横条遮挡。

#### 预期效果

- 顶部功能不再丢失。
- 底部导航项从 8 个减为 4+1，空间更充裕，误触降低。
- 符合主流 App（如微信、钉钉）的底部 Tab 交互认知。

### 4.2 侧边栏（`aside`）组件

#### 当前问题

底部导航标签文字 9–11 px，图标 20 px，无分组分隔，当前态仅背景高亮，在深色背景下不够醒目。

#### 优化策略

1. **组件形态**：保持底部固定栏，但重新设计：
   - 背景使用 `var(--bg-surface)` + 顶部 1 px 细线 + 微弱阴影。
   - 非当前项图标颜色 `var(--text-muted)`，文字 `var(--text-secondary)`。
   - 当前项图标颜色 `var(--primary-light)`，文字 `var(--text-primary)`，并在图标上方增加 3 px × 18 px 的圆角短横线作为激活指示器。
2. **"更多"入口**：使用一个"更多"（或"菜单"）图标，点击后从底部弹出半屏面板，显示剩余入口及分组标题（如"用户功能""管理后台"）。
3. **手势支持**：底部导航栏支持左右轻扫切换相邻常用 Tab（可选增强，需 JS）。

### 4.3 顶部栏（`header.topbar`）组件

#### 当前问题

被完全隐藏。

#### 优化策略

引入 `.mobile-topbar`：

```
┌────────────────────────────────────┐
│  Factorio Manager        ☰ 👤     │  44 px 高
└────────────────────────────────────┘
```

- 左侧显示当前页面名称或品牌名。
- 右侧"菜单"按钮触发操作表，包含：
  - 检查更新（带 spinning 状态）
  - 版本号（可点击，打开版本信息弹窗）
  - 个人资料
  - 退出登录（红色文字，二次确认）
- 避免在 `.topbar` 原类上直接修改，通过新增 `.mobile-topbar` 类在移动端渲染独立结构。

### 4.4 徽章（`span.badge`）组件

#### 当前问题

`.badge` 使用 `text-transform: uppercase`（对中文无效）、圆角 999 px、固定 padding，在标题行中并排时容易折行。

#### 优化策略

1. **新增移动端变体 `.badge-mobile`**：
   - 高度固定 22 px，padding 3 px 8 px。
   - 字号 11 px，字重 600，不使用大写。
   - 圆角 11 px（胶囊形但不过于夸张）。
   - 移除 `pulse-glow` 动画，改为左侧 3 px 纯色竖条装饰（更工业风、更省空间）。
2. **在密集区域使用点状状态**：实例卡片标题右侧若空间不足，可将文字徽章简化为带 `title` 提示的彩色圆点 + 隐藏文字。
3. **徽章组合规则**：同一行最多展示 2 个徽章，其余折叠到"更多"提示中。

### 4.5 实例详情页头部（`div.instance-page-header`）

#### 当前问题

标题行包含返回按钮、名称、徽章、状态、ID、操作按钮，小屏下折行后逻辑顺序混乱。

#### 优化策略

将实例详情头部在移动端重排为三层：

```
┌────────────────────────────────────┐
│ ← 实例名称              [⋮ 更多]   │  标题行
│ 运行中 · 默认 · v2.0.76            │  元信息行（可横向滚动）
│ [启动] [停止] [刷新]                │  操作按钮行（全宽或自适应）
│ 概览  配置  存档  Mod  ...          │  标签页（图标+文字）
└────────────────────────────────────┘
```

1. **标题行**：返回按钮 + 实例名称 + 右侧"更多"按钮（将刷新、编辑等次要操作收纳）。
2. **状态元信息行**：将状态徽章、版本、端口、运行时间等信息横向排列，空间不足时允许横向滚动（`overflow-x: auto`，隐藏滚动条），避免折行。
3. **操作按钮行**：根据状态显示"启动"或"停止"，按钮高度 40 px（触控友好），宽度在 480 px 以下可占满半行，危险操作保持 `window.confirm` 二次确认。
4. **标签页**：在 480 px 以上显示"图标 + 短文字"；在 375 px 极端小屏下可仅显示图标，但保留 `title` 属性提示，且默认显示前 4 项 + "更多"下拉。

### 4.6 标签页（`.tabs` / `.instance-tabs`）

#### 当前问题

全局 `.tabs` 已支持横向滚动，但实例详情 `.instance-tabs` 在 768 px 以下隐藏文字，认知成本高。

#### 优化策略

1. **统一标签页规范**：
   - 标签最小宽度 64 px，高度 40 px。
   - 当前指示器从底部 2 px 线改为底部 3 px 圆角粗线，颜色 `var(--primary)`。
2. **实例详情标签**：
   - 在 480 px 以上显示"图标 + 2 字简称"（如"概览""配置""存档""日志"）。
   - 在 480 px 以下显示图标 + 1 字简称，或在标签数量 > 5 时使用可滚动的完整标签。
3. **滚动提示**：当标签可滚动时，右侧显示 16 px 的渐变淡出遮罩，提示用户还有更多内容。

### 4.7 卡片（`.card`）与网格

#### 当前问题

卡片在移动端仍有较强阴影和 16 px 内边距，视觉偏重；`.stat-grid` 在 480 px 以下单列，但 768 px 时两列仍可能让数值被截断。

#### 优化策略

1. **移动端卡片**：
   - 内边距 16 px，圆角 10 px。
   - 阴影从 `shadow-md` 降至 `shadow-sm` 或仅保留 1 px 边框，减少层次压迫感。
   - 标题与内容间距从 16 px 降至 12 px。
2. **统计网格**：
   - 在 768 px 以下统一单列（当前 768 px 为两列，480 px 才单列），确保数值和标签不被挤压。
   - 统计卡片改为横向布局：左侧图标/标签，右侧数值，一行展示，提升扫视效率。
3. **实例卡片网格**：
   - 保持单列，但卡片内部采用更紧凑的 3 行结构：标题/状态、关键信息、操作按钮。
   - 状态徽章固定在右上角，避免与标题挤占空间。

### 4.8 表格（`.table-wrap`）

#### 当前问题

`table { min-width: 600px; }` 在 375 px 屏幕上横向滚动幅度大，表头 sticky 后滚动条位置不明确。

#### 优化策略

1. **优先卡片化**：对于实例列表、用户管理、订单等数据，在 <= 768 px 下将表格行转换为卡片列表，每行一个卡片，关键信息纵向排列，操作按钮在卡片底部。
2. **保留横向滚动作为降级**：仅当字段较多且无法卡片化时（如配置页 JSON 预览）才使用横向滚动，且滚动容器增加左右 12 px 内边距，提示可滑动。
3. **表头优化**：卡片化后不再显示表头，改用每卡片的顶部小标签说明数据类型。

### 4.9 表单（`.form-row`、`.form-field`）

#### 当前问题

表单标签 12 px 大写、字间距 0.6 px，在移动端阅读困难；表单项垂直堆叠后间距 10 px 稍显拥挤。

#### 优化策略

1. **标签样式**：移动端改为 13 px 常规大小写，字重 600，颜色 `var(--text-secondary)`，行高 1.4。
2. **输入框高度**：保持 40 px（触控友好），字体 16 px（避免 iOS 缩放页面）。
3. **表单分组**：使用 `.form-section` 将相关字段分组，每组之间 20 px，组内字段 12 px。
4. **操作按钮**：表单提交/取消按钮在移动端垂直堆叠，主按钮置顶（符合拇指操作），危险操作（如删除实例）使用红色描边按钮而非实心红色，避免误触。

### 4.10 模态框（`.modal-card`）

#### 当前问题

移动端模态框宽度 `calc(100% - 32px)`，但在小屏上按钮组可能折行，更新进度弹窗内容居中但空间利用率不高。

#### 优化策略

1. **移动端模态框**：
   - 宽度 92 vw，最大宽度 420 px，圆角 12 px。
   - 在小屏（<= 480 px）下支持从底部滑入（`translateY(100%) -> translateY(0)`），更像原生操作表。
2. **底部按钮组**：
   - 主/次按钮垂直堆叠，高度 44 px。
   - 关闭按钮位于右上角，尺寸 40×40 px。
3. **版本更新弹窗**：进度条区域增加上下内边距，百分比与步骤文字分开两行，避免拥挤。

### 4.11 配置页（`.config-layout`）

#### 当前问题

240 px 固定左侧配置类型边栏无移动端适配，小屏下内容被严重挤压。

#### 优化策略

1. **移动端配置页重构**：
   - 将左侧配置类型列表改为顶部可横向滚动的选择器（类似标签页）。
   - 配置文件列表（Profiles）折叠为一个下拉选择框（`<select>`），默认收起。
   - 编辑区占满剩余空间，操作按钮固定在编辑区底部。
2. **分步编辑模式（可选）**：
   - 第一步选择配置类型 + 文件。
   - 第二步进入编辑页，顶部显示返回按钮和当前文件名。

## 5. 交互优化建议

### 5.1 触控目标

- 所有可点击元素最小触控区域 44×44 px（WCAG 2.1 AA 建议）。
- 底部导航项目标区域 48×48 px。
- 按钮最小高度：普通 40 px，重要操作 44 px，底部固定操作 48 px。
- 表格卡片化后，整行可点击区域扩大，操作按钮间距 ≥ 8 px。

### 5.2 手势与动效

| 手势 | 应用场景 | 实现方式 |
|------|---------|---------|
| 左滑返回 | 从实例详情返回实例列表 | 监听 `touchstart`/`touchend`，滑动距离 > 80 px 且水平角度 < 30° 触发返回 |
| 底部导航左右滑动 | 在常用 Tab 间快速切换 | 与底部导航栏事件绑定，切换当前路由 |
| 下拉刷新 | 实例列表、日志、玩家列表 | 页面顶部下拉触发数据重新加载 |
| 长按操作 | 实例卡片显示快捷操作菜单 | 长按 500 ms 弹出操作菜单（启动/停止/删除） |
| 双指缩放 | 日志终端、JSON 编辑器 | 仅当内容区聚焦时允许缩放，默认禁用页面缩放 |

> 注意：手势实现需考虑与浏览器默认行为的冲突，建议通过 `touch-action: pan-y` 限制横向滑动区域的默认行为。

### 5.3 操作反馈

1. **点击态**：所有按钮和列表项在 `:active` 时背景变亮 8%，或透明度降至 0.85，反馈延迟 ≤ 100 ms。
2. **加载态**：按钮加载时显示 spinner 并禁用按钮，避免重复提交。
3. **Toast 提示**：将当前 `alert` 内联消息改为顶部 Toast 或底部 Snackbar，不推挤布局，3 秒后自动消失。
4. **危险操作二次确认**：停止、删除、回退等操作保持 `window.confirm`，在移动端应使用原生 `confirm`（系统样式，最可靠）。

### 5.4 导航与信息架构

1. **面包屑**：在移动端实例详情页增加简化面包屑：`实例 > 名称 > 当前标签`，帮助用户定位。
2. **返回按钮统一**：所有非首层页面左上角放置返回按钮，尺寸 40×40 px。
3. **空状态优化**：空状态图标缩小至 40 px，文字 14 px，操作按钮紧跟下方，垂直居中于可视区域（扣除底部导航）。

### 5.5 键盘与输入法

1. 输入框聚焦时页面不可整体放大（iOS 默认会缩放 16 px 以下字体），确保输入框字体 ≥ 16 px。
2. 数字输入框（如端口、数量）使用 `inputmode="numeric"`。
3. 表单底部提交按钮不被虚拟键盘顶起遮挡，必要时使用 `position: fixed` 底部固定。

## 6. 适配标准

### 6.1 设备矩阵

| 设备 | 尺寸 | 验证优先级 |
|------|------|-----------|
| iPhone SE / 同类小屏 Android | 375 × 667 | 高 |
| iPhone 12/13/14/15 | 390 × 844 | 高 |
| iPhone 14 Pro Max / 大屏 Android | 430 × 932 | 高 |
| iPad mini 竖屏 | 768 × 1024 | 中 |
| iPad Air 横屏 | 1180 × 820 | 中 |
| 桌面 1920 × 1080 | 1920 × 1080 | 高 |

### 6.2 浏览器兼容性

- Chrome / Edge（Android）最新 2 个主版本。
- Safari（iOS）最新 2 个主版本。
- Samsung Internet 最新 1 个主版本。
- 不支持 IE。

### 6.3 性能标准

- 首屏渲染时间（FCP）<= 1.5 s（4G 网络）。
- 交互响应时间（FID）<= 100 ms。
- 动画帧率 >= 55 fps。
- 避免在移动端使用大面积 blur 滤镜和复杂渐变动画。

### 6.4 可访问性标准

- 文字与背景对比度 >= 4.5:1（正文），>= 3:1（大号文字/图标）。
- 所有图标按钮具备 `aria-label`。
- 底部导航当前项使用 `aria-current="page"`。
- 模态框打开时焦点锁定，关闭后返回触发按钮。
- 支持系统级字体大小调整（不使用固定 px 禁止缩放，但可使用 `rem` 适配）。

## 10. 风险与注意事项

1. **功能不丢失原则**：移动端不应为了空间而隐藏核心功能（如当前 `.topbar` 被整体隐藏），应提供替代入口。
2. **桌面端回归风险**：所有移动端样式应通过媒体查询或独立类名限定，避免影响桌面端已有布局。
3. **第三方组件依赖**：当前项目使用 Lucide 图标，新增"更多""汉堡"等图标时应使用现有图标库，避免引入新依赖。
4. **性能影响**：新增手势、动画、底部固定栏不应显著增加主线程负担，复杂手势建议 debounce/throttle。
5. **React Router 兼容性**：底部导航、手势返回等需与 `react-router-dom` 的 `NavLink`/`useNavigate` 配合，避免重复导航或状态丢失。
6. **热更新版本号规则**：按项目规则，本次优化若作为独立功能迭代，应增加中版本号；若作为 bug 修复/体验优化，可增加小版本号。建议作为"体验优化"合集递增小版本号。
