# P3 聊天 / 投票 / 玩家 / 定时消息 开发

## 第一章：问题分析

### 问题现象
P2 完成后，面板仍缺少 factorio 原项目核心竞争力中的：
- 聊天监控与触发响应（chat_settings / chat_trigger_responses）
- 投票踢人系统（votes / vote_records / vote_settings）
- 玩家加入欢迎与首次礼包（player_join_settings）
- 玩家绑定与历史（player_bindings / player_histories）
- 定时消息广播（periodic_messages）
- 礼包领取记录查询（gift_claims）

### 影响范围
- 模块0（Panel 后端 + 前端）
- 公共契约层（panel-api-types.ts / errors.ts）

### 根因分析
S4 P3 阶段未实现，需基于已 migration 的 P3 数据表（20260703000008/09/10）开发对应服务+路由+前端页面。

## 第二章：修复方案

### 方案描述
采用 subagent 并行 + 主线程整合策略：
- subagent A：chatService + voteService + 路由 + 前端页面
- subagent B：playerService + periodicMessageService + 路由 + 前端页面
- 主线程：扩展公共契约（panel-api-types.ts + errors.ts）+ 提取 requireAdmin 到 middleware/auth.ts + 整合 index.ts + 整合 api/client.ts + 整合 App.tsx/Layout.tsx

### 替代方案
- 单线程串行开发：耗时过长，且 P3 模块间无强依赖，适合并行
- 拆分更多 subagent：单批并行上限 2（与 s0203 对齐），避免协调成本

### 风险评估
- 并行写 index.ts/client.ts 会冲突 → 通过"subagent 不修改整合文件，主线程统一整合"规避
- player.ts 混合 admin/user 权限 → 主线程统一套 requireAdmin 保守处理（普通用户 histories/claims 暂需 admin 代查）
