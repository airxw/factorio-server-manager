## 二、优化目标

### 总体目标
将前端从"功能可用"提升到"运维顺手、视觉统一、交互流畅"，使三种角色（server_admin / instance_admin / user）在桌面与移动端均能高效完成核心任务。

### 量化指标

| 维度 | 当前状态 | 目标状态 |
|------|---------|---------|
| 操作逻辑 | 12 项阻断/不一致问题 | 0 项高严重度、≤2 项低严重度 |
| 布局结构 | 12 项布局缺陷 | 0 项高严重度、≤3 项低严重度 |
| 页面美化 | 12 项视觉不一致 | 0 项高严重度、≤4 项低严重度 |
| 加载骨架覆盖率 | 约 15% 页面 | 100% 主流程页面 |
| 暗色模式 | 未实现 | 全站支持 |
| 移动端响应式 | 部分页面未验证 | 375px / 768px / 1024px / 1280px 四档断点全覆盖 |
| Lighthouse 性能分 | 未测量 | Performance ≥ 85、Accessibility ≥ 90、Best Practices ≥ 90 |

## 三、具体实施步骤

> 按"问题修复 → 体系化建设 → 美化升级"三阶段推进。每阶段独立可交付。

### 阶段一：阻断问题修复（对应 A01-A02、A05、B01、C04、C06）

#### 步骤 1.1 修复登录页 demo 账号按钮禁用
- 排查 Login.tsx 中 DEMO_ACCOUNTS 按钮的 disabled 条件
- 验证三个按钮（紫/蓝/绿）分别对应 admin/manager/user，点击即自动填充邮箱密码并提交登录
- 验证登录失败时的错误提示样式

#### 步骤 1.2 修复 `/instances/:id/shop` 路由 404
- 排查 App.tsx 路由表中 `/instances/:id/shop` 的 element 绑定
- 验证 Shop.tsx 在路径参数 `:id` 缺失时的兜底渲染
- 验证从实例详情"商店管理"Tab 跳转到独立商城页的链接正确性

#### 步骤 1.3 修复商城品质选择未按 Pack 配置动态显示
- Shop.tsx / ShopItems.tsx 读取当前实例 Pack 的 `support_quality` 和 `quality_tiers`
- `support_quality=false` 时隐藏品质选择控件
- `quality_tiers=0` 时默认选中"无品质"且不可切换
- Factorio（quality_tiers=5）展示完整品质下拉

#### 步骤 1.4 修复实例详情 Tab 横向溢出
- Tab 容器增加 `overflow-x: auto` + 自定义滚动条样式
- Tab 项增加 `flex-shrink: 0` + `white-space: nowrap`
- 窄屏下当前激活 Tab 自动滚动到可视区域

#### 步骤 1.5 修复状态徽标颜色对比度
- 重新定义 `badge-warning` / `badge-error` / `badge-success` / `badge-info` 的前景色与背景色组合
- 通过 WCAG AA 对比度校验（≥ 4.5:1）
- 黄底配深棕字、红底配白字、绿底配白字、蓝底配白字

#### 步骤 1.6 提升加载骨架屏覆盖率
- 列表页（实例列表、版本列表、用户列表、审计日志等）统一使用 Skeleton 行占位
- 表单页（创建实例、个人设置、系统配置）使用 Skeleton 字段占位
- Tab 内首屏加载使用 Skeleton 卡片占位，替代"加载中…"纯文字
- 抽象 `<ListSkeleton />` / `<FormSkeleton />` / `<TabSkeleton />` 三个通用组件

### 阶段二：操作逻辑与布局体系化（对应 A03-A12、B02-B12）

#### 步骤 2.1 修复 Tab 切换竞态
- ServerDetail.tsx 的 useEffect 监听 `searchParams` 时，若 `tabFromUrl` 不在当前 `tabs` 列表，先暂存到 `pendingTab` state
- `uiTabs` 加载完成后，若 `pendingTab` 在最终 `tabs` 中则切换
- 避免初始化阶段因 tabs 未就绪被回落到 console

#### 步骤 2.2 补全 Console Tab 空状态
- 实例停止时显示"实例未运行，控制台暂不可用"插画 + 启动按钮
- RCON 输入框 disabled 时增加 tooltip 解释原因
- 实例运行但无日志时显示"等待日志输出…"骨架动画

#### 步骤 2.3 增加创建实例后首次配置引导
- 创建成功跳转详情页后，检测 `current_version` 为空 → 弹出引导弹窗
- 引导步骤：确认端口 → 确认 RCON → 接受 EULA（如 Pack 声明 `eula_required`）→ 跳转到"游戏更新"Tab 选版本
- 提供"跳过引导"入口

#### 步骤 2.4 统一表单校验反馈
- 定义全局 `<FieldError />` 组件，统一 inline 红字样式 + 图标
- 移除部分页面的 toast 校验、弹窗校验
- 校验时机统一为 onBlur + onSubmit，避免 onChange 频繁报错

#### 步骤 2.5 统一危险操作确认机制
- 定义 `<DangerConfirm />` 组件，支持三档危险等级：
  - 低（删除版本、删除 Mod）：ConfirmDialog 二次确认
  - 中（删除用户、重置密码）：输入用户名确认
  - 高（删除实例、清空存档）：输入实例名 + 显示影响范围清单
- 全站危险操作替换为该组件

#### 步骤 2.6 修复旧 admin 链接重定向后引导
- `/instances` 页面读取 `?uiTab=` 参数，若存在则：
  - 高亮提示"请选择实例以打开 XX 功能"
  - 用户点击实例后自动跳转到详情页对应 Tab

#### 步骤 2.7 版本下载进度持久化
- 下载进度写入 `sessionStorage`（按 task_id 索引）
- 版本管理页 mount 时恢复进行中的进度
- 跨标签页通过 `storage` 事件同步

#### 步骤 2.8 表格列宽自适应
- 实例列表：名称列 flex-grow、状态/Pack/版本列 width:auto、操作列 width:fixed
- 用户列表、审计日志、Pack 列表等长表格统一采用相同模式
- 中小屏自动隐藏次要列（如创建时间、节点名）

#### 步骤 2.9 移动端导航去重
- 移动端（<768px）隐藏侧边栏抽屉，仅保留底部导航
- 底部导航增加"更多"项，弹出二级菜单（系统管理、版本管理、个人设置）
- 桌面端保留侧边栏，隐藏底部导航

#### 步骤 2.10 Modal 宽度分级
- 定义三档宽度：
  - 小（确认框、提示）：400px
  - 中（表单、详情）：600px
  - 大（编辑器、复杂表单）：800px 或 90vw
- 全站 Modal 标注级别，统一替换

#### 步骤 2.11 表单对齐统一
- 全站表单采用"顶部 label + 全宽控件"布局（移动端友好）
- 桌面端中等宽度（768-1024px）下双列表单
- 移除 CreateServer / Profile / SystemConfig 之间的对齐差异

#### 步骤 2.12 商城聚合页增强
- `/shop` 顶部增加全局商品搜索框
- 增加分类筛选侧栏（item/block/tool/armor/weapon/food）
- 增加品质筛选（仅 Pack.support_quality=true 时显示）

### 阶段三：美化与体验升级（对应 C01-C12）

#### 步骤 3.1 建立全局 CSS 变量系统
- 定义 `:root` 下的颜色变量（primary/secondary/success/warning/error/info/neutral × 9 级）
- 定义间距变量（4/8/12/16/24/32/48px 标尺）
- 定义圆角变量（sm/md/lg/full）
- 定义阴影变量（sm/md/lg）
- 全站硬编码颜色/间距替换为变量

#### 步骤 3.2 建立字体层级系统
- 定义 6 级字体层级：
  - H1: 24px / 700 / 1.3
  - H2: 20px / 600 / 1.4
  - H3: 18px / 600 / 1.4
  - Body: 14px / 400 / 1.5
  - Caption: 12px / 400 / 1.5
  - Overline: 11px / 600 / 1.4（uppercase）
- 全站标题/正文/辅助文字替换

#### 步骤 3.3 阴影/边框统一
- 卡片：`shadow-sm` + `border 1px solid var(--border)`
- 弹窗：`shadow-lg` + 无边框
- 悬浮元素：`shadow-md`
- 移除散落的自定义 box-shadow

#### 步骤 3.4 空状态插画与引导
- 定义 6 类空状态插画：无数据、无搜索结果、无权限、错误、未运行、空文件夹
- 每类空状态配主文案 + 副文案 + 引导按钮（如"创建第一个实例"）
- 全站空状态替换为该组件

#### 步骤 3.5 图标统一
- 全站统一使用 lucide-react，移除 emoji 和自定义 SVG
- 定义图标尺寸标准（16/18/20/24/32px）
- 定义图标颜色标准（继承当前文字颜色）

#### 步骤 3.6 按钮主次关系强化
- 定义四级按钮：
  - Primary（主操作）：实心蓝
  - Secondary（次操作）：边框灰
  - Ghost（幽灵）：无边框
  - Danger（危险）：实心红
- 同一页面仅一个 Primary 按钮
- 主操作按钮固定在右下角或表单底部

#### 步骤 3.7 Modal 过渡动画
- 进入：opacity 0→1 + translateY 10px→0，200ms ease-out
- 离开：opacity 1→0 + translateY 0→10px，150ms ease-in
- 遮罩层 opacity 0→1，200ms
- 使用 CSS transition 实现，避免引入额外动画库

#### 步骤 3.8 暗色模式实现
- 使用 CSS 变量 + `prefers-color-scheme` 媒体查询
- 侧边栏页脚增加主题切换按钮（亮/暗/跟随系统）
- 主题选择持久化到 localStorage
- 三套色板：亮色、暗色、品牌蓝

#### 步骤 3.9 实例详情 Tab 激活态强化
- 激活 Tab：背景色 `var(--primary-50)` + 字重 600 + 底部 2px 实线 `var(--primary-500)`
- 非激活 Tab：背景透明 + 字重 400 + hover 时背景 `var(--neutral-100)`

#### 步骤 3.10 版本信息弹窗日志条目类型徽标
- 解析 version.md 中每条日志的前缀（新增/修复/破坏性/优化）
- 渲染对应颜色徽标：新增=绿、修复=蓝、破坏性=红、优化=黄
- 未识别前缀默认灰色

#### 步骤 3.11 配置文件编辑器高度优化
- 编辑器高度 = `calc(100vh - 280px)`，最小 400px
- 内部不滚动，跟随页面滚动
- 文件较长时显示行号侧栏 + mini-map

#### 步骤 3.12 诊断结果结构化展示
- `/admin/diagnostics` 结果按类别分组（数据库/文件系统/网络/Daemon/Panel）
- 每类可折叠展开
- 异常项红色高亮 + 修复建议链接

## 四、技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| CSS 变量管理 | 原生 CSS Custom Properties + `:root` | 无需额外依赖，浏览器原生支持，可与暗色模式媒体查询无缝配合 |
| 暗色模式 | `prefers-color-scheme` + 手动切换类 `data-theme="dark"` | 兼顾系统跟随与用户主动选择 |
| 骨架屏组件 | 自研 `<Skeleton />` / `<ListSkeleton />` / `<FormSkeleton />` | 现有 Skeleton 已可用，仅需扩展为组合形态 |
| 空状态插画 | 内联 SVG（自定义绘制 6 类） | 避免引入图标库体积，可按需染色 |
| Modal 动画 | CSS transition + React state 控制挂载时序 | 避免引入 framer-motion 等动画库 |
| 表单校验 | react-hook-form + zod | 与后端 zod schema 复用，类型安全 |
| 危险确认 | 自研 `<DangerConfirm />` | 三档危险等级需定制化，第三方库无法覆盖 |
| 图标库 | lucide-react（保持现状） | 已全站使用，仅清理 emoji 和散落 SVG |
| 移动端响应式 | CSS Media Query + 移动优先断点 | 375 / 768 / 1024 / 1280 四档 |
| 性能监控 | Lighthouse CI + Web Vitals | 部署前回归 |
| Tab 滚动 | 自定义 scroll-into-view + IntersectionObserver | 无需引入 carousel 库 |
