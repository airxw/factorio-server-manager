## SOFT_BLOCK 处置决策

### SB-R3-H1（高优先级）— R3-11 问题 2: 撤销失败不回滚
- **位置**: `panel/backend/src/services/userService.ts:660-669` + `panel/backend/src/core/auth/tokenBlacklist.ts:113-136`
- **问题**: `updateUserRoles` 中 `revokeAllUserTokens` 失败时静默继续（不回滚），角色降级后旧 JWT 仍可用旧角色权限，最长 24h 窗口期
- **风险**: 真实安全风险，但影响场景需满足 ①DB 异常 + ②用户角色被降级 + ③旧 JWT 未过期 三条件同时成立
- **处置**: 已知悉放行，v4.17.1 修复
- **修复路径**: `updateUserRoles` 中检查 `revokedTokenCount`，若为 0 且非重复撤销（对比 existing.token_version 与 currentVersion），抛出异常回滚事务或记录 CRITICAL 级告警

### SB-R3-M1（中优先级）— R3-11 问题 1: 契约/实现不一致
- **位置**: `panel/backend/src/services/userService.ts:657` vs `public/interface_stub/user-service.d.ts:197`
- **问题**: 契约声明 `activeRole ∉ roles` 抛 `InvalidCredentialError`，实现却调用 `resolveActiveRole` 静默降级到 `roles[0]`（与 `selectActiveRole` 行 725-727 行为不一致）
- **风险**: 调用方按契约编写代码会预期异常，但实际拿到降级后的用户对象
- **处置**: 已知悉放行，v4.17.1 修复
- **修复路径**: 修改 `updateUserRoles` 实现，在 `resolveActiveRole` 之前显式校验 `activeRole ∈ normalizedRoles`，不通过抛 `InvalidCredentialError`（与 `selectActiveRole` 行为对齐）

### SB-R3-L1（低优先级）— R3-3 + R3-4: 事务保护 + 角色切换不撤销
- **位置**:
  - R3-3: `panel/backend/src/core/auth/tokenBlacklist.ts:113-136`（SELECT + UPDATE 未事务保护）
  - R3-4: `panel/backend/src/services/userService.ts:714-755`（selectActiveRole 不撤销旧 token）
- **问题**:
  - R3-3: `revokeAllUserTokens` 三步操作未事务保护，DB 异常 + 旧用户（token_version=0）场景下黑名单失效
  - R3-4: 角色切换不撤销旧 token，审计归属可能混淆（用户先用 instance_admin 操作，切换回 user 后用旧 token 继续 instance_admin 操作）
- **风险**: 影响面窄，不构成越权（用户只能切换到自己已拥有的角色）
- **处置**: 已知悉放行，v4.18.0 周期处理
- **修复路径**:
  - R3-3: 将 SELECT + UPDATE 包在 knex transaction 内
  - R3-4: 在 `selectActiveRole` 中追加审计日志；v4.18.0 考虑角色权限降级（高→低）时强制撤销旧 token
