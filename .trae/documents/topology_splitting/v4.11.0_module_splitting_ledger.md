# v4.11.0 商业化重构模块拆分与编排台账

## 一、 模块划分与边界定义

根据 `public/` 目录下的商业化契约与 Mock 资源，我们将 v4.11.0 的开发任务拆分为以下 3 个核心业务模块。所有模块必须严格遵守“只依赖 `public/` 契约，禁止跨模块直连内部实现”的原则。

| 模块命名 | 物理路径 | 核心职责 | 输入 | 输出 |
|---------|----------|----------|------|------|
| **模块1_资产管理后端** | `panel/backend/src/modules/asset_service/` | 实现 `IAssetService`，处理全局资产与实例资产的 CRUD 及 Merge 逻辑。 | `public/schema/*.json` <br> DB 实例 | REST API 路由与 Controller |
| **模块2_商业化控制台前端** | `panel/frontend/src/admin/commercial/` | 系统管理员与实例管理员的资产管理 UI。 | `public/interface_stub/` <br> `MockAssetService` | 商业化管理页面组件 |
| **模块3_指令沙箱与执行引擎** | `daemon/src/modules/execution_engine/` | 实现 `IExecutionEngine`，处理防注入校验与 RCON 变量替换。 | `public/config_template/` <br> `error_codes.json` | 沙箱执行服务 |

**并行约束声明**：本阶段最大并行度设为 2（前端与后端并行）。任何分支失败，仅回退该分支自身代码，不影响公共契约与其他分支。

## 三、 跨模块协作约束与 `public/` 边界
1. **Frontend ↔ Backend**: 前端开发期间（P1-B），必须将 API 调用的底层逻辑指向 `public/pre_generated_mock/mock_asset_service.ts`。直到合流测试（S6）前，前端不得要求后端提供真实的 API 端点。
2. **Backend ↔ Daemon**: 后端在调用 RCON 执行时，必须依赖 `IExecutionEngine` 接口定义，严禁后端直接拼装 Shell 命令。
3. **隔离保护**: 任何一个 `parallel-sub-agent` 分支都**没有**修改 `public/` 目录的权限。如果开发中发现契约不合理，必须触发 `s0601` 契约变更流程，而不能私自改动。
