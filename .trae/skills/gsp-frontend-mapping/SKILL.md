# GSP 前端页面梳理（Mapping）

本技能用于把“前端页面梳理”变成可检索、可持续迭代的文档资产：以路由为索引，输出页面说明、用户路径流程、关键接口与异常、关键实现定位（代码引用），并在梳理过程中持续写入日志。

## 0. 适用场景（何时调用）

- 用户提出：要做“全前端页面梳理 / 页面盘点 / 路由与页面关系梳理”
- 用户提出：从某个页面开始梳理（如 `https://gsp.ecsrz.com:3001/login`）
- 用户要求：梳理过程中的记录需要落盘在 `docs/` 下，避免检索困难

## 1. 产出物（落盘位置固定）

所有产出落盘在 `docs/frontend/`：

- 引导页：`docs/frontend/README.md`
- 页面文档：`docs/frontend/pages/<slug>.md`
- 流程文档：`docs/frontend/flows/<slug>.md`
- 梳理日志：`docs/frontend/logs/YYYY-MM-DD.md`
- 模板：`docs/frontend/templates/page-template.md`

## 2. 前置约束（必须遵守）

- 浏览器端访问地址只允许使用项目合法入口（例如 `https://gsp.ecsrz.com:3001`），不得引导或记录任何 `localhost:3000` / `127.0.0.1:3000` 作为浏览器访问地址。
- 记录策略：只新增/更新 `docs/frontend/**` 文档，不删除存量文档；若信息需要替换，采用“更新并在日志记录变更点”的方式。

## 3. 执行步骤（标准流程）

### 3.1 初始化/修复文档骨架

若不存在则创建，若已存在则校验并补齐：

1. `docs/frontend/README.md`：包含页面索引表、流程索引表、标记体系、强制字段约定
2. `docs/frontend/templates/page-template.md`：页面梳理模板
3. 确保目录存在：`pages/`、`flows/`、`logs/`、`templates/`

### 3.2 建立当日日志

- 创建/追加 `docs/frontend/logs/YYYY-MM-DD.md`
- 写入“今日目标 / 进展记录 / 待办”
- 每完成一个页面梳理，追加一条“已完成项”与“证据”（页面文档链接、关键代码引用链接）

### 3.3 针对一个页面进行梳理（推荐从用户指定 URL 开始）

对用户指定的页面（如 `/login`）执行：

1. 创建或打开 `docs/frontend/pages/<slug>.md`（若不存在则用模板生成）
2. 使用浏览器访问该页面，完成可见行为核对并记录：
   - 表单字段/校验/交互细节
   - loading/disabled/错误提示/空态
   - 权限与跳转（成功/失败/未登录）
3. 在代码中定位关键实现并写入“关键实现定位（代码引用）”：
   - 路由入口（React Router 配置或 App 路由聚合）
   - 页面组件文件
   - 关键 hooks / API client 调用 / 跳转逻辑（如登录成功回跳 `/`，由 RootRedirect 二次分流）
4. 补齐接口与异常：
   - `[API]` 接口路径/方法/鉴权要求
   - 常见失败：401/403/422/500/网络错误的 UI 映射

### 3.4 维护索引

每新增/完成一个页面或流程文档，需要同步更新：

- `docs/frontend/README.md` 的“页面索引”表：路由、页面文档、状态、备注
- `docs/frontend/README.md` 的“流程索引”表：流程名、文档、备注

### 3.5 流程文档（把多个页面串起来）

对一个“用户路径”（如登录与角色分流）：

1. 创建 `docs/frontend/flows/<slug>.md`
2. 按“目标/前置/主流程/失败与回退/关键接口/页面引用/风险待办”结构填写
3. 引用相关页面文档（相对链接即可）

## 4. 文档规范（强制字段 + 标记体系）

### 4.1 页面文档强制字段（标题必须一致）

1. 页面定位
2. 入口与路由
3. 角色与权限
4. 核心功能点
5. 交互流程
6. 接口与数据
7. 状态管理与副作用
8. 错误与边界
9. 体验与一致性检查
10. 关键实现定位（代码引用）
11. 待办与风险

### 4.2 标记体系（便于全局搜索）

- `[ROUTE]`：路由或 URL
- `[API]`：接口（路径/方法/鉴权/错误码）
- `[STATE]`：页面状态（loading、error、空态等）
- `[EDGE]`：边界条件（网络失败、权限不足、重复提交等）
- `[UX]`：体验与一致性问题
- `[TODO]`：可执行待办
- `[RISK]`：风险（线上/安全/数据/回归影响）

## 5. 代码引用写法（必须可点击）

在“关键实现定位”中使用以下格式：

- 单文件：`[Login.tsx](file:///ABSOLUTE/PATH/TO/Login.tsx)`
- 指定行号：`[App.tsx:L120-L180](file:///ABSOLUTE/PATH/TO/App.tsx#L120-L180)`

## 6. 完成判据（页面级）

当且仅当满足以下条件，页面可标记为“已完成梳理”：

- 页面文档 11 个强制字段已填充（允许少量“待确认”但必须标注原因）
- 至少包含 1 处可点击代码引用（路由或页面组件）
- 当日日志中记录了该页面完成，并附页面文档链接
