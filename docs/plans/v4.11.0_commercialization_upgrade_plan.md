# GSP v4.11.0 商业化重构升级方案

> **文档元信息**
> - **版本**: v4.11.0 (中版本升级)
> - **状态**: 方案规划 (Planning)
> - **核心定位**: 从“运维管理面板”向“B2B2C游戏私服商业化 SaaS 平台”转型

## 一、 升级背景与核心定位
现有的 GSP 项目已具备基础的 Panel-Daemon 架构和实例管理能力。为打破开源面板工具的同质化竞争，v4.11.0 版本将打通“游戏私服商业化最后一公里”，实现 **B2B2C 的商业闭环**：
- **平台方（System Admin）** 提供基础设施与变现工具（卖水人）。
- **服主（Instance Admin）** 利用工具运营游戏、获取流水（零售商）。
- **玩家（User）** 在服主专属页面中消费时间与特权（消费者）。

## 二、 角色与权限模型演进

### 2.1 系统管理员 (System Admin) —— 供应链与规则制定者
- **核心职能**: 维护物理节点、系统稳定性、提供标准化的商业变现“预制菜”。
- **新增能力**:
  - **全局模板库管理**: 配置默认商品（如 VIP卡、基础道具）、默认价格、默认欢迎词。
  - **底层执行逻辑封装**: 将不同游戏的底层发货、加白名单指令（RCON）封装为统一的 API，供上层调用。
  - **租户配额管理**: 设定服主可以创建的实例数量、玩家上限及生命周期（正常、停机、冷备、销毁）。

### 2.2 实例管理员 (Instance Admin) —— 零售商与微创业者
- **核心职能**: 选品、定价、本地化营销、玩家社群运营。
- **新增能力**:
  - **继承与重写 (Override)**: 在全局模板基础上，一键上架商品，仅需修改表现层数据（价格、上下架状态），无需接触底层代码。
  - **高阶自定义能力 (UGC)**: 允许高级/Mod服主自行创建商品，并编写对应的 RCON 执行变量指令（支持自定义 Mod 变现）。
  - **CRM 玩家管理**: 可视化的玩家列表，支持发放补偿、封禁、手动调整时长。

### 2.3 普通用户 (User) —— 消费者
- **核心职能**: 浏览商城、购买特权、消耗游戏时长。
- **新增体验**:
  - **玩家自助门户 (Player Portal)**: 极简的“店铺化”前端，屏蔽所有服务器运维信息。
  - **身份绑定与消费**: 绑定游戏 ID（如 Steam ID），通过卡密或直充兑换时长及虚拟商品。

## 三、 核心机制设计

### 3.1 模板与继承机制 (Template & Override)
- **数据结构**: 引入 `Global_Assets` (全局资产库) 与 `Instance_Assets` (实例资产库)。
- **逻辑流向**: 实例创建时，自动挂载 `Global_Assets`；当服主修改某个商品价格时，在 `Instance_Assets` 生成一条 Override 记录。玩家端展示时进行数据 Merge。

### 3.2 动态指令沙箱与安全隔离
- **问题**: 允许实例管理员自定义发货指令存在命令注入风险。
- **方案**:
  - 引入 **RCON 指令沙箱**: 所有自定义指令中的变量（如 `{player_id}`）必须经过严格的正则过滤与转义。
  - **爆炸半径控制**: 指令的执行权限被严格锁定在当前实例的 Daemon 进程范围内，严禁跨实例或触及宿主机 Shell。

## 四、 UI/UX 重构方向

1. **Platform Dashboard (系统后台)**: 偏向大盘数据监控、资源分配、全局模板管理。
2. **GM Workbench (服主工作台)**: 偏向“店铺后台”风格，弱化终端命令行，强化“商城管理”、“玩家列表”、“数据报表”。
3. **Player Portal (玩家门户)**: 移动端优先的 C 端电商体验，包含服主自定义 Banner、商品列表、账号绑定卡片。

## 五、 实施路径与迭代计划

### Phase 1: 基础设施与数据结构改造 (当前版本)
- 设计并实现 `Global_Assets` 和 `Instance_Assets` 数据库表结构及 Merge 逻辑。
- 重构权限中间件，严格区分三类角色的 API 访问边界。

### Phase 2: 全局模板与基础变现闭环
- 系统管理员后台：增加“全局商品/模板”配置界面。
- 服主工作台：增加“商城管理”页面，支持商品上架与改价（Override）。
- 玩家门户：上线基础的充值与卡密兑换页面。
- **核心验证**: 玩家兑换卡密 -> 触发系统预设 RCON 指令 -> 游戏内生效。

### Phase 3: 高阶自定义与生态反哺
- 开放实例管理员的“自定义商品与底层指令”配置权限。
- 引入指令安全过滤沙箱。
- 构建基础的“租户账单与时长统计”仪表盘。
