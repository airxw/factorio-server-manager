# 正式功能测试矩阵（v4.16.3 基线 / demo 数据清理后）

> 本文档在 v4.16.3 demo 数据清理成果落生产后产出，作为正式功能测试的执行蓝图。

## 一、测试目标与范围

### 1.1 测试目标

- 验证 demo 数据移除后，正式功能在真实数据下完整可用，作为后续 v4.17.0 统一绑定重构与 business-logic-v1 落地的基线。
- 覆盖 admin（服务器管理员）/ manager（实例管理员）/ user（玩家）三角色视角的完整业务流程。
- 在生产环境 `https://gsp.ecsrz.com:3001` 上验证端到端链路，包含鉴权、数据展示、写操作、跨模块联动。

### 1.2 测试范围（In Scope）

| 域 | 覆盖内容 |

| 服务器管理（admin） | 创建 / 启动 / 停止 / 重启 / 删除 / 配置 / 文件 / 备份 / 存档 / 监控 |

### 1.3 测试范围外（Out of Scope）

- v4.17.0 统一绑定重构尚未完成的部分（多角色切换 UI、新权限点端点挂载）——本基线仅验证 B3-B5 已闭合的鉴权基座。
- business-logic-v1 契约下游实现（s0202 Mock 生成 / s0203 模块拆分 / 实例有效期 / VIP 积分 / 钱包退款 / 优惠券）——契约已冻结但实现未开始。
- Daemon 节点端真实游戏进程启停（仅做 Mock 路径连通性验证，不真正启动 Minecraft/Rust 等游戏服务端）。

- 无 P0/P1 缺陷（崩溃/数据丢失/安全漏洞）
- P2 缺陷 ≤ 5 个且均有 workaround
- P3 缺陷登记到 backlog，不阻断基线建立
- 三角色视角均完成核心链路验证
- 测试报告归档到 `.trae/documents/test_reports/formal_test_<date>/`

## 八、缺陷处理流程

1. 发现缺陷 → 记录到 `.trae/documents/defects/<date>_<module>_<short_desc>.md`
2. 缺陷分级：P0（崩溃/数据丢失）/ P1（核心功能不可用）/ P2（功能异常有 workaround）/ P3（体验问题）
3. P0/P1 立即阻断测试，触发 L3 信号（AskUserQuestion）裁决修复 vs 继续
4. P2/P3 登记后继续测试，测试结束后统一评审
5. 修复后回归测试该用例 + 关联用例
