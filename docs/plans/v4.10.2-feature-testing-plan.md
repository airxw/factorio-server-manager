# 全栈功能测试落地规划 (v4.10.2)

> 标识：`[V]` 价值判断与架构定稿节点。需 GN-004 与人类双重裁决。

## 一、测试背景与目标
项目已清理历史债务并完成了业务线瘦身。但由于此前缺乏系统性的功能测试，核心链路（特别是 Master-Slave 集群化架构下的实例生命周期）的鲁棒性未经验证。
**目标**：依据 AC 范式（s0402精神），从后端到前端建立“单测 -> E2E -> Mock回归”的三重质量防线，彻底覆盖“实例生命周期”这一核心链路。

## 二、三阶段执行方案

### 阶段一：后端 API 测试 (实例生命周期核心流)
- **测试目标**：`panel/backend/src/services/serverService.ts` 及对应的路由。
- **涵盖用例**：
  1. **创建实例 (Create)**：校验能否基于 `minecraft-vanilla` Pack 成功在数据库分配记录。
  2. **启动实例 (Start)**：拦截对 Daemon 的实际调用（Mock `daemonClient`），校验状态流转（stopped -> starting）。
  3. **停止实例 (Stop)**：测试停止指令的发放机制与鉴权。
  4. **删除实例 (Delete)**：测试安全删除校验（防误删）以及级联清理。
- **技术栈**：Vitest + in-memory SQLite。

### 阶段二：Daemon 进程调度与配置解析测试
- **测试目标**：`daemon/src/core/runner.ts` 及配置解析模块。
- **涵盖用例**：
  1. **配置读取**：针对 `minecraft-vanilla` 或 `factorio-vanilla`，测试能否正确解析 `pack.yaml`。
  2. **命令组装**：验证能否将用户设置（如最大内存、服务器名称）正确映射为底层执行参数。
  3. **生命周期拦截**：验证启动/停止指令能否触发对应的子进程方法（不真正启动外部进程，Mock `child_process`）。
- **技术栈**：Vitest。

### 阶段三：前端 UI 与交互测试 (s0402 规范)
- **测试目标**：面板服务器列表页及控制按钮交互。
- **涵盖用例**：
  1. **状态渲染**：基于 Mock 数据，测试 `ServerList` 组件能否正确显示在线/离线样式。
  2. **指令下发**：测试点击“启动”按钮后，能否正确调用对应的 API（拦截 HTTP 请求）。
  3. **状态同步**：模拟收到 WebSocket 状态变更事件，测试界面能否实时刷新为 `running`。
- **技术栈**：Vitest + React Testing Library。
