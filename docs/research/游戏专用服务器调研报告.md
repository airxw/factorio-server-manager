## 游戏1：Dyson Sphere Program（戴森球计划）

### Steam App ID

| 项目 | 值 |
|------|-----|
| 游戏本体 App ID | **1366540** |
| 专用服务器 App ID | **无官方专用服务器**（需使用游戏本体 + Nebula Mod） |

来源：[Steam 商店页](https://store.steampowered.com/app/1366540/Dyson_Sphere_Program/)

### 关键问题：是否有官方 Linux 专用服务器？

**没有官方专用服务器（Linux 或 Windows）。** DSP 是纯单机游戏，官方未提供任何专用服务器二进制。多人联机完全依赖社区 mod **Nebula Multiplayer Mod**（开源项目，GPL-3.0 license）。

- 官方游戏仅有 Windows 版本（`DSPGame.exe`）
- **没有 Linux 原生 server 二进制**
- 在 Linux 服务器上必须通过 **Wine/Proton** 运行 Windows 的 `DSPGame.exe`
- 玩家也必须安装 Nebula Mod 才能加入服务器（**服务器和客户端都需要安装 mod**）

来源：
- [Nebula Mod Thunderstore 主页](https://new.thunderstore.io/c/dyson-sphere-program/p/nebula/NebulaMultiplayerMod/)
- [Nebula Mod GitHub 仓库](https://github.com/NebulaModTeam/nebula)

### Nebula Mod 工作原理

- 基于 BepInEx 框架的 mod，通过 WebSocket（TCP）协议传输数据包
- **服务器和客户端都需要安装 mod**（包括 BepInEx 框架、NebulaMultiplayerMod、NebulaMultiplayerModApi 等依赖）
- 服务器以 headless 模式运行（`-batchmode -nographics -nebula-server`），不渲染图形
- 玩家通过游戏内"多人联机"菜单输入 `IP:Port` 加入

来源：[Nebula Mod GitHub Wiki - Hosting and Joining](https://github-wiki-see.page/m/PhantomGamers/nebula/wiki/Hosting-and-Joining)

### SteamCMD 下载

由于没有独立的服务器 App ID，必须通过 SteamCMD 下载**游戏本体**（App ID 1366540），这要求 Steam 账户拥有该游戏：

```bash
steamcmd +login <username> <password> +force_install_dir ~/dsp-server +app_update 1366540 validate +quit
```

> ⚠️ 注意：**不支持 anonymous 下载**，必须使用已购买 DSP 的 Steam 账户登录。
> 若只有一个 Steam 账户，可使用 [Steam 离线模式](https://help.steampowered.com/en/faqs/view/0E18-319B-E34B-B2C8) 同时在客户端和服务器运行。
> 也可在游戏目录创建 `steam_appid.txt` 内容为 `1366540` 以绕过 Steam 登录（但仍需已购买）。

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)

### 启动命令

**Windows 原生（推荐）：**
```powershell
./DSPGAME.exe -batchmode -nographics -nebula-server -load-latest
```

**Linux 通过 Wine：**
```bash
wine ./DSPGame.exe -batchmode -nographics -nebula-server -load-latest
```

> 若使用 r2modman 等模组管理器，启动参数需附加 BepInEx doorstop 参数：
> ```
> --doorstop-enable true --doorstop-target "<path>/BepInEx/core/BepInEx.Preloader.dll"
> ```

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)

### 启动参数列表

#### Unity 引擎参数

| 参数 | 说明 |
|------|------|
| `-batchmode` | 以 headless 模式运行，不显示画面、不接收用户输入 |
| `-nographics` | 在 batchmode 下不初始化图形设备 |
| `-logFile <pathname>` | 指定 Unity 日志文件路径 |
| `-hidewindow 1` | 启动时不弹出窗口 |

#### Nebula 专用参数

| 参数 | 说明 |
|------|------|
| `-nebula-server` | **核心参数**：以专用 headless 服务器模式启动 DSP |
| `-load <savename>` | 加载指定名称的存档（不存在则退出） |
| `-load-latest` | 加载存档目录中最新的存档 |
| `-newgame <seed> <starCount> <resourceMultiplier>` | 以和平模式新建游戏，3 个参数：种子、星系数、资源倍率 |
| `-newgame-cfg` | 使用配置文件 `BepInEx/config/nebulaGameDescSettings.cfg` 新建游戏 |
| `-newgame-default` | 使用游戏默认设置新建游戏 |
| `-ups <float>` | 设置 UPS（逻辑帧率），范围 5-240，使用 `FPSController.SetFixUPS(value)` |

> ℹ️ **任务描述中提到的 `-server` 参数并不存在**，正确参数是 `-nebula-server`。

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)、[DeepWiki - Advanced Topics](https://deepwiki.com/NebulaModTeam/nebula/8-advanced-topics-and-troubleshooting)

### 就绪日志特征

Nebula Mod 默认关闭 BepInEx 控制台窗口。需在 `BepInEx/config/BepInEx.cfg` 中将 `Logging.Console` 节的 `Enabled = false` 改为 `Enabled = true` 才能看到状态输出。

- 启动后控制台会显示 BepInEx 加载日志和 Nebula 初始化信息
- 服务器就绪后会监听配置的端口（默认 **8469 TCP**）
- **任务描述中"UDP 10800"是错误的**——Nebula 默认使用 **TCP 8469**，不是 UDP，也不是 10800

建议的就绪判断方式：
1. 监听端口 8469 是否成功绑定
2. 日志中出现 Nebula 启动完成相关行（具体文本需根据 BepInEx 控制台输出确认）

来源：[Nebula Mod Thunderstore 主页](https://new.thunderstore.io/c/dyson-sphere-program/p/nebula/NebulaMultiplayerMod/)（原文："The mod uses TCP for direct connections, with the default port set to 8469."）

### 停止命令

- **Ctrl+C**：发送中断信号，服务器会先将当前游戏保存为 `_lastexit_.dsv`，然后退出（这是优雅关闭方式）
- 无独立的 stop 命令；通过进程信号控制

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)

### 配置文件

#### 主配置文件：`BepInEx/config/nebula.cfg`

关键字段：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `AutoPauseEnabled` | `true` | 无玩家连接时自动暂停游戏 |
| `RemoteAccessEnabled` | `false` | 允许认证的客户端执行远程服务器命令 |
| `RemoteAccessPassword` | （空） | 客户端执行远程命令所需的认证密码 |
| `ServerPassword` | （空） | 服务器加入密码（非空时客户端需输入密码） |

#### 网络配置（在游戏内 Settings → Multiplayer，或 `nebula.cfg` 中）：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `Host Port` | **8469** | 服务器监听端口（TCP） |
| `Enable UPnP/Pmp Support` | false | 启用路由器 UPnP/PMP 自动端口转发 |
| `Enable Experimental Ngrok support` | false | 启用内置 Ngrok 内网穿透 |
| `Ngrok Authtoken` | （空） | Ngrok 用户 token |
| `Ngrok Region` | 自动 | us/eu/au/ap/sa/jp/in |

#### 新游戏配置：`BepInEx/config/nebulaGameDescSettings.cfg`

包含 `[Basic]`、`[Combat]`、`[General]` 三个分区，定义种子、星系数、资源倍率、和平模式、战斗参数等。

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)

### 存档目录

| 路径 | 说明 |
|------|------|
| `%USERPROFILE%\Documents\Dyson Sphere Program\` | Windows 默认存档根目录 |
| `~/.wine/drive_c/users/<user>/Documents/Dyson Sphere Program/` | Linux Wine 环境 |
| `Saves/*.dsv` | 游戏存档文件 |
| `<SaveName>.server` | 多人玩家数据文件（与存档同名，**迁移时必须一起复制**） |
| `player.key` | 玩家身份密钥（位于存档目录上层；删除后将以新玩家身份加入） |
| `_lastexit_.dsv` | Ctrl+C 退出时自动保存的存档 |

来源：[Nebula Wiki - Setup Headless Server](https://github.com/NebulaModTeam/nebula/wiki/Setup-Headless-Server)

### 玩家 / 物品 / 聊天命令

Nebula 提供完整的聊天命令系统，所有命令以 `/` 开头，通过游戏内聊天窗口（默认 `Alt + Backtick` 打开）执行。

#### 服务器远程管理命令（需先开启 `RemoteAccessEnabled`）

| 命令 | 用法 | 说明 |
|------|------|------|
| `/server login [RemoteAccessPassword]` | `/server login hunter2` | 认证以获取服务器管理权限 |
| `/server list [saveNum]` | `/server list 5` | 显示最近 N 个存档（按时间排序） |
| `/server save [saveName]` | `/server save backup1` | 保存当前游戏；未指定名称则保存为 `_lastexit_` |
| `/server load <saveName>` | `/server load save1` | 加载指定存档（当前游戏会先存为 `_lastexit_` 再重启） |
| `/server info` | `/server info` | 显示服务器 `/info` 命令的输出 |

#### 玩家管理命令

| 命令 | 别名 | 说明 |
|------|------|------|
| `/who` | `/players`、`/list` | 列出所有在线玩家及其位置 |
| `/whisper <player> <message>` | `/w`、`/tell`、`/t` | 私聊玩家 |
| `/info` | — | 显示服务器 IP、端口、运行时间、游戏版本、Mod 版本；`/info full` 显示完整 Mod 列表 |
| `/playerdata list` | — | 列出所有存储的玩家数据 |
| `/playerdata load <hashString>` | — | 通过 hash 或玩家名加载玩家数据 |
| `/playerdata remove <hashString>` | — | 删除玩家数据（仅主机） |

#### 聊天 / 导航命令

| 命令 | 别名 | 说明 |
|------|------|------|
| `/help [command]` | `/h`、`/?` | 列出所有命令或显示某命令详情 |
| `/clear [all]` | `/c` | 清空聊天消息（`all` 包括玩家消息） |
| `/system [star name]` | `/s` | 列出星系所有星球 |
| `/navigate <target>` | `/n` | 设置导航目标（行星/恒星/玩家）；`/n clear` 清除 |
| `/ping [delay]` | — | 测试连接 |
| `/reconnect` | `/r` | 快速重连服务器 |

#### 开发者命令

| 命令 | 别名 | 说明 |
|------|------|------|
| `/xconsole [cmd]` | `/x` | 执行开发者控制台命令（如 `/x -upsfix 120`） |
| `/dev sandbox` | — | 切换沙盒模式 |
| `/dev load-cfg` | — | 从 `nebulaGameDescSettings.cfg` 重载游戏设置 |
| `/dev self-destruct` | — | 自毁玩家机甲 |
| `/dev unload-factories` | — | 卸载所有工厂（仅客户端，在太空中） |

#### 物品给予命令

> ⚠️ **Nebula Mod 没有原生的 `/giveitem` 命令**。
> - 沙盒模式下可通过游戏内 sandbox 工具栏给予物品
> - 高级用户可通过 `/xconsole` 执行底层开发者命令（XConsole）实现类似功能，但非官方支持

来源：[Nebula Wiki - Chat Commands](https://github.com/NebulaModTeam/nebula/wiki/Chat-Commands)

### 默认端口

| 端口 | 协议 | 用途 |
|------|------|------|
| **8469** | **TCP** | Nebula WebSocket 通信端口（默认，可在 `nebula.cfg` 修改） |

> ❗ **重要纠正**：任务描述中"默认端口（UDP 10800）"是错误的。
> - Nebula Mod 使用 **TCP 8469**（不是 UDP）
> - 端口 10800 与 DSP/Nebula 无关
> - 协议为 WebSocket（基于 TCP），不支持 UDP

来源：[Nebula Mod Thunderstore 主页](https://new.thunderstore.io/c/dyson-sphere-program/p/nebula/NebulaMultiplayerMod/)（原文："The mod uses TCP for direct connections, with the default port set to 8469."）

### 必需变量（pack.yaml 中 `{{var}}` 占位符）

```yaml
{{steam_username}}      # 必须已购买 DSP 的 Steam 账户
{{steam_password}}      # Steam 密码（建议使用 Steam Guard 离线 token）
{{server_install_dir}}  # 安装目录，如 /home/dsp/server
{{save_name}}           # 加载的存档名（用于 -load 参数），或使用 -load-latest
{{nebula_port}}         # 默认 8469
{{server_password}}     # 服务器加入密码（可选）
{{remote_access_password}}  # 远程管理密码（可选）
{{auto_pause}}          # 无玩家时是否自动暂停，默认 true
{{ups}}                 # 逻辑帧率，默认 60，范围 5-240
{{new_game_seed}}       # 新游戏种子（仅 -newgame 模式）
{{new_game_star_count}} # 新游戏星系数（默认 64）
{{new_game_resource_mult}}  # 新游戏资源倍率（默认 1.0）
```

### Linux 专用服务端二进制

> ⚠️ **Enshrouded 没有原生 Linux 二进制**。服务器是 Windows 可执行文件 `enshrouded_server.exe`，在 Linux 上必须通过 **Wine** 运行。

| 文件名 | 平台 |
|--------|------|
| `enshrouded_server.exe` | Windows（原生）+ Linux（通过 Wine） |

Linux Wine 环境依赖安装：
```bash
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install wine wine64 wine32 lib32gcc-s1 libsdl2-2.0-0:i386 -y
```

来源：[gameserverguides Linux 指南](https://gameserverguides.com/enshrouded/setup-guide/linux)

### 启动命令

**Windows：**
```powershell
enshrouded_server.exe
```

**Linux（Wine）：**
```bash
cd ~/enshrouded-server
wine enshrouded_server.exe
```

> Enshrouded 服务端**不接受命令行启动参数**，所有配置通过 `enshrouded_server.json` 文件完成。

### 启动参数列表

**Enshrouded 服务端不通过命令行参数配置**。所有可配置项均位于 `enshrouded_server.json` 中。首次启动时服务器会自动生成默认配置文件然后退出，编辑后再启动即可。

### 就绪日志特征

启动后服务器会输出初始化日志，当出现以下标志时表示服务器就绪：

- **`Host_Online`**：服务器已上线，开始接受连接（这是核心就绪标志）
- 启动过程可能持续数分钟，特别是首次启动 Wine 环境初始化

来源：[redswitches 指南](https://www.redswitches.com/blog/enshrouded-dedicated-server-setup/)（原文："Once it finishes, restart your server and confirm Host_Online appears."）

### 停止命令

- **无控制台 stop 命令**
- 通过进程信号停止：`Ctrl+C` 或 `kill <pid>`
- 若使用 systemd 管理：`systemctl stop enshrouded`


### 配置文件

DST 采用多文件分层配置，位于 `<persistent_storage_root>/<conf_dir>/<cluster>/` 目录：

#### 1. `cluster.ini`（集群级配置）

```ini
[GAMEPLAY]
game_mode = survival            ; survival/endless/wilderness
max_players = 16
pvp = false
pause_when_empty = true

[NETWORK]
cluster_name = My Dedicated Server
cluster_description = Welcome!
cluster_password =
cluster_language = en
tick_rate = 60

[MISC]
console_enabled = true
max_snapshot_packet_size = 10240

[SHARD]
shard_enabled = true            ; 启用多分片
bind_ip = 127.0.0.1
master_ip = 127.0.0.1          ; Caves shard 连接 Master 的 IP
master_port = 10888            ; 分片间通信端口（UDP loopback）
cluster_key = supersecretkey   ; shard 间认证密钥（Master 和 Caves 必须一致）
```

#### 2. `cluster_token.txt`（Klei 账户 Token）

文件内容为一行字符串（必填）：

```
pds-^KXXXXXXXXXXXXXXXXXXXXXX==_<userid>
```

> ❗ **没有此 Token 服务器无法上线**，详见 [EULA / Token 要求](#eula--token-要求-4) 章节

#### 3. `Master/server.ini`（地表分片配置）

```ini
[NETWORK]
server_port = 10999            ; Master 游戏 UDP 端口

[SHARD]
is_master = true               ; 标记为主分片

[STEAM]
master_server_port = 27016
authentication_port = 8766
```

#### 4. `Caves/server.ini`（洞穴分片配置）

```ini
[NETWORK]
server_port = 10998            ; Caves 游戏 UDP 端口

[SHARD]
is_master = false
name = Caves

[STEAM]
master_server_port = 27017
authentication_port = 8767
```

> ℹ️ 多 shard 部署时，Master 和 Caves 的 Steam 端口必须不同（避免冲突）。

来源：[Klei 官方 - 多分片配置指南](https://forums.kleientertainment.com/forums/topic/65557-guide-setting-up-a-dedicated-server-with-caves/)、[DST Wiki - Server Configuration](https://dontstarve.fandom.com/wiki/Guides/Don%E2%80%99t_Starve_Together_Dedicated_Server)

### 默认端口

| 端口 | 协议 | 用途 | 配置位置 |
|------|------|------|----------|
| **10999** | **UDP** | Master shard 游戏端口（玩家连接） | `Master/server.ini [NETWORK] server_port` |
| **10998** | **UDP** | Caves shard 游戏端口（玩家连接） | `Caves/server.ini [NETWORK] server_port` |
| **8766** | **UDP** | Steam 认证端口（Master 用） | `Master/server.ini [STEAM] authentication_port` |

### EULA / Token 要求

#### ❗ 强制 Token 要求（无 Token 服务器无法上线）

DST 专用服务器**必须**获取 Klei 账户的 Cluster Token，写入 `<cluster>/cluster_token.txt` 文件。

**Token 获取流程：**

1. 注册 Klei 账户：https://accounts.klei.com/
2. 登录后访问：https://accounts.klei.com/account/info
3. 复制 **KU_ ID**（用户 ID，格式如 `KU_xxxxxxxx`）
4. 进入游戏（单机或服务器均可），按 `~` 打开控制台，执行：
   ```
   TheNet:GenerateClusterToken()
   ```
5. 这会生成 Token 文件到本地存档目录，文件名 `cluster_token.txt`
6. Token 格式：`pds-^K<base64>=_<KU_id>`
7. 将该文件复制到服务器的 `<cluster>/cluster_token.txt`

**替代方案（无需客户端游戏）：**

通过 Klei 账户网页生成：
1. 访问 https://accounts.klei.com/account/serverTokens
2. 点击 "Generate New Token"
3. 复制生成的 Token 字符串
4. 直接写入 `<cluster>/cluster_token.txt`

> ⚠️ **Token 与 KU_ ID 绑定**：每个 Klei 账户可生成多个 Token，但 Token 仅能识别所属账户。**Token 不可分享**，分享后他人可冒用账户身份创建服务器。

#### EULA

- **无独立 EULA 接受流程**：SteamCMD 下载即视为接受 Steam Subscriber Agreement
- DST 服务端受 Klei EULA 约束（与游戏本体一致）

#### 其他要求

- **无需 Steam 账户购买**：anonymous 下载即可
- **无需游戏客户端**：纯服务端运行
- **IPv4 必须绑定 `0.0.0.0`**：默认绑定 localhost 会导致外部无法连接

### 启动参数列表

Terraria 服务端采用 `-key value` 或 `-key=value` 两种格式（推荐 `-key value`）。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-config <file>` | — | 指定配置文件路径（**推荐使用**，所有配置集中管理） |

| `-players <n>` / `-maxplayers <n>` | 8 | 最大玩家数（1-255） |
| `-pass <pass>` / `-password <pass>` | （空） | 服务器加入密码 |

| `-worldname <name>` | World | 自动建图时使用的世界名 |

| `-banlist <file>` | banlist.txt | 封禁列表文件路径 |
| `-secure` | — | 启用 anti-cheat 保护（封禁异常连接的 IP） |
| `-noupnp` | — | 禁用 UPnP 自动端口转发 |
| `-steam` | — | 启用 Steam 联机模式（仅 Steam 版客户端可加入） |

| `-forcepriority` | — | 强制进程优先级 |
| `-seed <seed>` | — | 世界生成种子（字符串） |
| `-worldpath <path>` | `~/.local/share/Terraria/Worlds/` | 世界文件存储目录 |

### 就绪日志特征

Terraria 服务器启动后日志中会出现以下标志表示就绪：

- **`Listening on port 7777`**（核心就绪标志，端口随配置变化）
- **`Server started`**（服务器进入接受连接状态）

  ```
  Terrariav<version>
  Listening on port 7777
  ```

```bash
grep -E "Listening on port|Server started" server.log
```

> ⚠️ 注意：Terraria 服务端默认**不输出日志文件**，所有日志输出到 stdout。需要通过 systemd journal 或重定向到文件保留。

### 停止命令

### 配置文件

#### 主配置文件：`serverconfig.txt`

采用 `key=value` 格式（非 INI 分区），位于服务端安装目录或自定义路径：

```text
# 服务器基础配置
world=/home/terraria/Worlds/MyWorld.wld
worldname=MyWorld
autocreate=2
seed=
worldpath=/home/terraria/Worlds/
difficulty=0                  ; 0=经典、1=专家、2=大师、3=旅途
port=7777
maxplayers=16
password=MyServerPassword
upnp=0                        ; 1=启用 UPnP，0=禁用

# 安全配置
secure=1                      ; 1=启用 anti-cheat
banlist=banlist.txt

# Steam 配置
steam=false                   ; true=仅 Steam 客户端可加入
lobby=private                 ; friends/private/none

# 语言
language=en-US                ; en-US/zh-Hans/ja-JP/fr-FR/de-DE/it-IT/pt-BR/ru-RU/es-ES/pl-PL

# 自动保存
autosave=300                  ; 自动保存间隔（秒），默认 300
```

#### 关键字段说明

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `world` | — | 加载的 .wld 世界文件**绝对路径**（必填或使用 autocreate） |
| `worldname` | World | 自动建图时的世界名 |
| `autocreate` | — | 自动建图尺寸：1=小、2=中、3=大 |
| `seed` | （空） | 世界生成种子（自定义世界） |
| `worldpath` | `~/.local/share/Terraria/Worlds/` | 世界文件存储目录 |
| `difficulty` | 0 | 难度：0=经典、1=专家、2=大师、3=旅途 |
| `port` | 7777 | 游戏 TCP 端口 |
| `maxplayers` | 8 | 最大玩家数 1-255 |
| `password` | （空） | 服务器加入密码 |
| `secure` | 1 | 启用 anti-cheat |
| `banlist` | banlist.txt | 封禁列表文件路径 |
| `upnp` | 1 | 启用 UPnP 自动端口转发 |
| `steam` | false | 仅 Steam 客户端可加入 |
| `lobby` | none | Steam 大厅模式 |
| `language` | en-US | 服务器语言 |
| `autosave` | 300 | 自动保存间隔（秒） |

> ⚠️ **`world` 字段必须是绝对路径**，相对路径可能导致服务端在错误的工作目录下查找文件。

### 存档目录

| 平台 | 默认路径 |
|------|---------|
| Linux 服务端 | `<worldpath>` 或 `~/.local/share/Terraria/Worlds/` |
| Windows | `%USERPROFILE%\Documents\My Games\Terraria\Worlds\` |

#### 世界文件结构

```
~/.local/share/Terraria/Worlds/
├── MyWorld.wld            # 主世界文件（地图、Tile、NPC、物品）
├── MyWorld.twld           # Tile 数据文件（Terraria 1.4+ 拆分存储）
└── MyWorld.bak            # 自动备份（最近一次保存的副本）
```

| 文件 | 说明 |
|------|------|
| `<worldname>.wld` | 主世界存档（必备份） |
| `<worldname>.twld` | Tile 实体数据（1.4+ 拆分，必须与 .wld 一起备份） |
| `<worldname>.bak` | 自动备份 |
| `banlist.txt` | 封禁列表（位于服务端工作目录） |
| `players/` | 玩家数据（仅原版客户端使用，服务端不存储玩家数据） |

> ⚠️ **备份时必须同时备份 `.wld` 和 `.twld`** 文件，单独恢复 .wld 会导致 Tile 实体（箱子内容、逻辑门等）丢失。

来源：[Terraria wiki - World Save Locations](https://terraria.wiki.gg/wiki/Save_file_location)、[tModLoader wiki](https://github.com/tModLoader/tModLoader/wiki/tModLoader-Dedicated-Server-Setup)

### 默认端口

| 端口 | 协议 | 用途 | 配置位置 |
|------|------|------|----------|
| **7777** | **TCP** | 游戏端口（玩家连接） | `serverconfig.txt port` 或 `-port` 参数 |

### EULA / Token 要求

#### EULA

- **无需接受 EULA**：SteamCMD 下载即视为接受 Steam Subscriber Agreement
- Terraria 服务端受 Re-Logic EULA 约束（与游戏本体一致）

#### Token

- **无需任何 Token**：SteamCMD 支持 anonymous 下载
- **无需 Klei/Steam 账户绑定**：服务端独立运行

#### 首次启动特殊要求

- **原版服务端**：无特殊要求，启动时若 `world` 字段为空且指定 `autocreate`，会自动创建新世界
- **TShock 服务端**：首次启动会在控制台输出 `setup_code.txt`，需用该 code 在游戏内执行 `/setup <code>` 获取初始管理员权限，然后 `/user add <username> <password> superadmin` 创建管理员账户

> ✅ **Terraria 是五个游戏中部署最简单的**：无 Token、无 EULA、无 Claim、支持 anonymous 下载、原生 Linux 二进制。

8. **cluster_key 必须一致**：Master 和 Caves 的 `cluster.ini [SHARD] cluster_key` 必须完全相同，否则 shard 间无法通信

## 调研总结

### 五个游戏的共同特征

1. **均无需 EULA 接受**：5 个游戏均无独立的 EULA 接受流程
2. **多数无 Token 要求**：仅 DST 需要 Klei Cluster Token，其他 4 个游戏均无 Token 要求

4. **多数支持手动 save 命令**：仅 Enshrouded 无手动存档命令，其他 4 个均支持
5. **多数支持 kick/ban 命令**：仅 DSP（通过 userGroups）和 Satisfactory（通过 Server Manager UI）无控制台命令

### 五个游戏的关键差异

| 维度 | DSP | Enshrouded | Satisfactory | DST | Terraria |
|------|-----|------------|--------------|-----|----------|
| 服务器来源 | 第三方 Mod | 官方 | 官方 | 官方 | 官方 |
| Linux 支持 | Wine | Wine | 原生 | 原生 | 原生 |

### 对 pack.yaml 的整体建议

1. **每游戏独立 schema**：5 个游戏配置体系差异巨大，建议每游戏独立 schema 文件
2. **命令支持矩阵**：在面板中显式标注每游戏支持的命令（kick/ban/giveitem/broadcast/save），不支持的灰显
3. **Linux 兼容性标识**：明确标识 Wine 包装需求（DSP、Enshrouded）vs 原生 Linux（Satisfactory、DST、Terraria）
4. **首次启动引导**：
   - DSP：需安装 BepInEx + Nebula Mod
   - Enshrouded：需先生成配置后退出再启动
   - Satisfactory：需 Claim 服务器
   - **DST：需配置 cluster_token.txt（强制）**
   - Terraria：无特殊要求（autocreate 自动建图）
5. **端口协议标识**：DSP 是 TCP、Terraria 是 TCP，其他是 UDP，pack.yaml 必须明确协议字段
6. **存档备份策略**：
   - DSP：`.dsv` + `.server` + `player.key`
   - Enshrouded：`savegame/` 目录
   - Satisfactory：`server/` 目录 + `ServerSettings.<PORT>.sav`
   - **DST：整个 `<cluster>/` 目录 + `cluster_token.txt`（必备）**
   - **Terraria：`.wld` + `.twld`（1.4+ 必须同时备份）**
7. **stdin 命令通道**：DST（Lua c_ 命令）、Terraria（控制台命令）、Satisfactory（quit）均通过 stdin 与服务端交互，daemon 需实现 stdin 写入能力
8. **多 shard / 多进程支持**：仅 DST 需要多进程（Master + Caves），其他游戏均为单进程，pack.yaml 需为 DST 提供 `multi_shard: true` 标志
9. **Token 获取引导**：仅 DST 需要 Klei Token，面板应提供 token 获取流程引导（注册 Klei 账户 → 生成 Token → 写入 cluster_token.txt）
10. **变体支持**：Terraria 支持 TShock 变体（不同 App ID 2465980），pack.yaml 应支持"原版 / TShock"切换

### 部署难度排序（从易到难）

1. **Terraria** ⭐ —— 无 Token、无 EULA、无 Claim、TCP 单端口、原生 Linux、autocreate 自动建图
2. **Satisfactory** ⭐⭐ —— 原生 Linux、但需 Claim 服务器、3 端口规划
3. **DST** ⭐⭐⭐ —— 原生 Linux、但需 Klei Token、多 shard 部署复杂
4. **Enshrouded** ⭐⭐⭐⭐ —— 需 Wine、首次启动生成配置后退出
5. **DSP** ⭐⭐⭐⭐⭐ —— 需 Wine + 已购买账户 + BepInEx + Nebula Mod，最复杂
