## 六、废弃 migration down() 清理（C5）

### 6.1 现状
`panel/backend/src/db/migrations/` 共 42 个迁移文件，每个文件都有 `up()` 和 `down()` 方法。部分 `down()` 方法在后续迁移重新创建表后已无实际回滚意义（例如 `dropTable` 后又被新迁移 `createTable`）。

### 6.2 执行步骤
- 逐个审查 42 个迁移文件的 `down()` 方法：
  - 若 `down()` 调用 `dropTable` 但该表在后续迁移中被重新创建或扩展 → 保留 `down()` 但添加注释说明"回滚将丢失后续迁移新增的字段"
  - 若 `down()` 调用 `dropColumn` 但该字段在后续迁移中被重新添加 → 同上
  - 若 `down()` 为空操作（`await knex.schema.withSchema(...).alterTable(...)` 无实际变更）→ 保留空 `down()` 但添加注释
- **不删除任何 `down()` 方法**（保留回滚能力，仅添加说明注释）
- 重点审查的迁移文件（创建表类）：
  - `20260703000001_create_core_tables.ts` ~ `20260703000013_add_claiming_at.ts`（13 个早期迁移）
  - `20260715100000_create_chat_logs.ts`
  - `20260716110000_add_monitoring_tables.ts`
  - `20260716160000_create_user_notifications.ts`
  - `20260717000001_create_system_update_jobs.ts`
  - `20260717000002_add_token_version_and_password_history.ts`
  - `20260718000000_create_game_versions.ts`
  - `20260728000000_create_password_resets.ts`
