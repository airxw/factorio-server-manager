# v4.0.2 演示模式（Demo Mode）执行方案

> 目标：将公开部署 `https://gsp.ecsrz.com:3001` 改造成"打开即看、一键登录、立即体验完整业务"的演示状态，适配参赛评委/客户评审场景。
> **不修改公共契约 `public/`，不改 nginx 配置，不改 HTTPS 架构**（v4.0.1 已稳定）。
> 本版本仅做"演示增强"——在现有功能之上叠加 demo 体验，零业务功能新增。

## 一、用户决策（已确认）

1. **一键登录**：3 个内置账号，按钮在登录页可见
   - `admin@local.dev` / `admin123` → 系统管理员（server_admin）
   - `manager@local.dev` / `admin123` → 实例管理员（instance_admin）
   - `user@local.dev` / `admin123` → 普通用户（user）

2. **演示数据**：5 个游戏 = 5 个示例实例 + 完整业务配套

   - 每个实例配套：1-2 个商店商品 + 1-2 个 CDK + 1-2 个聊天触发 + 1 个投票 + 1 个 Mod
   - 归属：示例实例 owner = `admin@local.dev`（server_admin 拥有所有实例可见性）

3. **初始化向导**：`/setup` 保留为可访问的 3 步流程，**走流程但不实际生效**（演示模式直接返回成功，不写 system_config）

4. **敏感操作**：全部允许执行，保留审计日志（v3.9.0-S10 已实现）

## 三、执行步骤

### D1 数据库改造

#### D1.1 新增 `is_built_in` 字段
- 新 migration：`20260801000000_add_is_built_in_to_users.ts`
- 字段：`is_built_in INTEGER NOT NULL DEFAULT 0`（0=普通，1=系统内置）
- 幂等：先 `hasColumn` 检查，存在则跳过
- 同步更新 demo seed（`migrations/20260717000000`）：插入时 `is_built_in=1`

#### D1.2 标记现有 demo 账号为内置
- 新 migration：`20260801000001_mark_demo_accounts_as_built_in.ts`
- 幂等：UPDATE 3 个 `*@local.dev` 邮箱的 `is_built_in=1`
- 防御：WHERE 条件带 `is_built_in=0` 避免重复更新

### D2 改密拦截

#### D2.1 `auth.ts` `/api/auth/change-password` 拦截
- 读取 `users.is_built_in`：若为 1 → 返回 403 `BUILT_IN_ACCOUNT_PASSWORD_READONLY`
- 错误码追加到 `public/schema/error-codes-schema.json`（**受保护路径**——需用户授权）

#### D2.2 前端 Users 管理页
- 内置账号行显示 "🔒 系统内置" 徽章
- 改密按钮 disabled + tooltip "系统内置账号密码不可修改"

### D3 生产环境开启 demo 模式

#### D3.2 重新构建前端

### F `/setup` 演示模式

#### F1 `createPublicInitRouter` 改造

  - `POST /api/init` → 接收任意入参，返回 200 `{ initialized: true, demo: true }`，**不写任何 system_config / 不改 admin 密码 / 不改 site.name**
- 当 `DEMO_MODE=false`（默认生产）：保持原行为

#### F2 `panel/backend/.env` / `.env.example`

## 五、风险与回退

### 风险 1：seed 脚本在生产数据库重复跑导致重复数据
- 缓解：`seedDemoDataIfMissing` 用 `WHERE NOT EXISTS` 检查 5 个实例 name 是否已存在
- 回退：人工 `DELETE FROM servers WHERE name LIKE '%演示服务器%'`

### 风险 2：`/api/init` demo 模式被真实部署误用
- 缓解：`DEMO_MODE` 默认 `false`，需部署者显式在 `.env` 启用
- 文档：在 `panel/backend/.env.example` 加醒目注释

### 风险 3：内置账号改密被拦截导致 user 误以为系统 bug
- 缓解：前端改密按钮 disabled + tooltip "系统内置账号密码不可修改"
- 错误码 403 + 友好提示："此为系统内置账号，密码不可修改"

### 风险 4：5 个示例实例占用端口
- 缓解：实例状态 = `stopped`（不实际启动），端口仅是声明
- 评委点"启动"才真正消耗资源
